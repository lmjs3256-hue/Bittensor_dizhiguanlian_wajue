# Bittensor 地址关联挖掘工具

版本：**0.8.6**

这是一个独立运行的 Bittensor 地址关联分析工具。输入公开地址后，工具可以调用 Taostats 历史转账索引，或查询本地 SQLite 索引，查找最多十级（默认三级）的普通 TAO 转账和子网 stake 转移关系。工具会把关联地址与人工维护的已知地址库匹配，并支持交易所、验证者和备注管理。

- 技术栈：FastAPI、SQLite、原生 HTML/CSS/JavaScript、`async-substrate-interface`
- 默认服务：<http://127.0.0.1:8766>
- 独立数据库：`data/wallet_link.db`
- 默认数据源：`wss://entrypoint-finney.opentensor.ai:443`

项目仓库：<https://github.com/lmjs3256-hue/Bittensor_dizhiguanlian_wajue>

> **第一次使用？** 直接看 **[使用说明.md](使用说明.md)**（或双击文件夹里的 `使用说明.html`，离线可看）：从装 Python 到导出地址的完整步骤、界面说明和常见问题都在里面。已经配好环境的话，双击 `启动.cmd` 就能用。

## 已实现

1. 输入 SS58 地址，最多执行十级 `Balances.Transfer` 关联扫描；默认仍为 3 级，层级只决定往下走几跳，单边门槛 / 累计门槛 / 交易所与公共地址截止等规则在每一级都一样。
2. 支持流入、流出、双向查询，以及单边金额与关系累计金额阈值。
3. 第一跳支持低于阈值的金额，第二跳及更深（最高 10 级）必须通过单边金额门槛；系统账户默认排除。
4. 人工导入 TXT、CSV、JSON 地址库；分类预置「大V / 群友 / 其他 / 系统」，支持自定义新增，且同一地址可属于多个分类（分类可随时人工修改）；EXCHANGE / VALIDATOR 为系统分类（过滤公共地址用）；「系统」分类与交易所同类：查到即作为关联终点、不再向下扩展，也可勾选「过滤系统地址」把它本身排除在结果外。
5. 查询结果只显示关联钱包地址、层级、流入/流出/累计金额和地址库标签，不展示交易明细；导出 JSON 也采用同一简化字段；另有“导出地址 TXT”，每行一个关联地址，便于直接复制到其他工具，并自动排除地址库中已确认的交易所地址和验证者地址。
6. 写入 SQLite 的转账均按事件去重，保留区块号、区块哈希、交易哈希与事件序号。
7. 扫描只读取公开链上事件，不签名、不转账、不修改钱包。
8. 可选调用 Taostats `GET /v1/transfers`，按地址扩展关系；页面显示单次请求数、分页状态、数据来源和部分结果提示。
9. 页面主题支持跟随系统、暖色护眼和深灰护眼，并在当前浏览器本地记住选择。
10. 地址扫描可以分别勾选过滤交易所和验证者；只有已人工确认的 `EXCHANGE` 地址才会过滤，未确认的疑似交易所会保留在结果中。
11. 关联地址和地址库地址都可以直接填写备注；地址库按标签折叠，同一标签默认只显示标签名称，点击后展开地址明细。
12. 已知交易所地址会显示明确标签；满足近 30 天高频转账、对手方多、可观察金额高且当前 free balance 达到门槛的地址，页面才会显示“疑似交易所（待确认）”，确认后才允许过滤；只观察到转账活动的地址，会显示“疑似中转钱包”。子网质押/解质押和购买事件仍未完整接入，这些自动标记都属于线索，不是身份结论。
13. SQLite 持久化统计本机实际发起的 Taostats 请求，页面显示今日、本月、累计、本月参考上限和本月剩余；缓存命中不计数。
14. 每次关联查询（分轮、单轮、中途停止）结束后自动保存一份查询记录；在“查询记录”页可以回看历史结果、重新导出关联地址（同样排除已确认交易所和验证者），最多保留最近 500 条（总体积超过 200 MB 时也会淘汰最旧记录）。
15. 关联结果和查询记录都支持“同步到已知地址库”：把关联地址与发起地址去重写入，已存在的地址一律跳过，不覆盖人工维护的分类、标签和备注；另提供“仅同步命中地址 + 发起地址”的入口。
16. 支持从查询结果“新建地址库并导入”：填写库名即可把本次关联地址和发起地址存成一个有名字的地址库，自动剔除已人工确认的交易所和验证者地址；地址库页提供按库查看、整库导出 TXT/CSV 和解散（解散会连同库里的地址一起删除，可用「撤回上次导入」恢复），地址库导出/导入均携带 `book` 字段。
17. 查询记录页提供“批量补录”：粘贴多个起始地址即可逐个重跑并自动归档，用于补回 0.3.0 之前没有落库的旧查询；可随时停止，批量内重复地址只跑一次。
18. 关联结果的地址后提供“复制”按钮；结果表支持全部、1 级 … 10 级筛选，筛选只改变当前显示，不重新消耗 API 请求。关联地址较多时自动分页：每页可选 10 / 20 / 50 / 100 条（默认 10 条），支持首页、上一页、输入页码跳转、下一页、末页。2/3 级地址的“路径明细”按「起始地址 → 当前地址」展示每一跳，并标注向外转出 / 对方转入；公共地址或未录入系统的交易所地址可在结果行上直接“标为交易所”，刷新后其下游噪音关联会自动消失。
19. 疑似交易所可以在关联结果或地址库中人工“确认交易所”“否定交易所”或重置结论。只有确认状态才允许交易所过滤；否定状态会持久化并阻止后续自动候选提示。
20. 自动交易所候选增加保守条件：只统计有时间戳的近 30 天转账，先读取 Bittensor `System.Account` 当前 free balance；余额低于 100 TAO、余额读取失败或缺少时间证据时，不自动认定为疑似交易所。当前余额查询最多检查 5 个候选，避免额外 RPC 请求失控。
21. 已确认的交易所公共地址是关联终点：结果保留交易所地址，但不会继续查询或展开该地址的下游钱包。与交易所公共地址直接发生转账的普通地址，即使只有一笔记录或余额为零，也会标记为“疑似中转钱包（交易所关联）”。
22. “已知地址库”页面支持导出 CSV 和 JSON，包含地址、名称、分类、备注、所属地址库及交易所人工确认/否定状态，可在其他设备通过导入文件恢复。
23. 扫描结果显示起始地址和关联地址的当前钱包余额；金额显示保留两位小数，关联地址默认隐藏为前四位和后四位，复制按钮仍复制完整地址。
24. 本地链上采集与 Taostats 查询都纳入 `SubtensorModule.StakeTransferred`（两个不同 coldkey 之间的子网 stake 转移）；边类型、源子网 ID 和 hotkey 在结果与导出中单独标识，金额按事件的 TAO 等值计价。
25. 地址库标签未填时默认取地址后四位（人工命名过的标记为自定标签，两者在清单里样式不同）；**改名和改分类都以「组」为单位**——点组标题右侧的「改名」「改分类」一次改整组，单条地址只改备注。整组改分类可多选（同时属于多个分类），交易所/验证者地址自动跳过，改完可「撤回上次导入」还原。
26. 同步地址库支持选择目标标签组：新查询命中已知地址库时，可把「新关联有效地址 + 扫描发起地址」去重**合并进已有地址库**（而不是另建一组）；没有命中时才新建地址库。工具栏提供**「撤回上次导入」**，删除新导入的地址并还原被改写的记录，防止无效关联被错误导入。
27. 外发包自带**预置地址库**：`app/seed_books/` 下每个 TXT 文件就是一个标签组（文件名即组名，同时也是同名自建库），首次启动自动装进已知地址库，装过之后重启不再重复导入，也不覆盖人工维护过的记录；解散或误删后可在工具栏点**「重新导入预置库」**补齐缺失地址（解散过的组连库带地址重建）。
28. 地址库清单的每个标签组标题右侧有**「全选本组」**勾选框和「已选 N」计数，可一次全选某组全部地址再批量删除或改分类；组内部分选中显示半选状态，与顶部「全选」和单条勾选互相同步。
29. 离线授权防泄漏：工具与电脑绑定，首次启动显示 16 位机器码，管理员签发 `WL1.` 开头的授权码激活（Ed25519 签名，程序内只放公钥）；未激活时业务接口全部 403，激活后页面右下角常驻团队水印、导出 TXT/JSON 带“授权给 …”溯源标记。授权默认**一机一码**，也可把多台机器码写进同一个码共用（单码最多 50 个机器码，即上限而非“自动 50 个席位”），详见 [授权管理.md](授权管理.md)。
30. **删除类操作都有二次确认**：删除单条地址、批量删除所选、删除分类、解散地址库、清空/删除查询记录、清除 API key 前都会弹确认框，并写清具体对象——单条删除显示地址、名称、所属库和分类，批量删除按组汇总「某组 N 条」；提示里还会说明能否撤回（解散地址库可用「撤回上次导入」恢复，单条/批量删除不可撤回，建议先导出备份）。
31. 关联地址除**层级筛选**外新增**金额筛选**：按流入 / 流出 TAO 设门槛，把只有零点几个 TAO 的「轻微关联」直接滤掉。口径有不限 / 流入或流出 ≥ / 流入 ≥ / 流出 ≥ / 累计 ≥ / 流入且流出 ≥；输入即时生效（不重新查询、不消耗 API），可与层级筛选叠加，表格下方显示「隐藏 N 条（显示 X / Y）」，条件记在浏览器本地。「导出地址 TXT」跟随当前金额筛选（导出即为筛完的干净清单），「导出 JSON」保留完整快照。
32. 人工判定交易所可以**随时改判**：结果表里已确认的地址显示「改为否定」「重置为待确认」，已否定的显示「改为交易所」「重置为待确认」，判错了一次点击就能翻转；改判不会冲掉人工起的组名（只有空名或系统自动名才替换）。地址库清单里每个标签组展开后还有「＋ 手动添加地址」，粘贴一批 SS58 地址（换行 / 逗号 / 空格分隔，单次最多 200 个）直接加进这一组，已存在的地址跳过、不改原记录，加错可「撤回上次导入」整体撤销。
33. 组内加地址遇到**已在别的组**的地址不会再静默跳过：会直接说「1 个已在「rrik」组，已跳过」，勾上「已在别的组的地址也移到本组」再点一次就能把它转到本组（改组名与分类，备注保留，可用「撤回上次导入」退回原组）。往「人工确认交易所 / 人工否定交易所」这两个组里加地址，会同步写入交易所人工结论，加进去就真的当交易所过滤。
34. **合并群组**：同一个种子扫出来、分散在几个库里交叉命中的地址，可以在地址库工具栏点「合并群组」，勾两个以上组一次合并成一个库——可以起新名字，也可以沿用其中一个原有组名。分类、备注、交易所人工结论逐条保留，合并后能用「撤回上次导入」退回原分组（被并掉的库名也一起恢复）。未命名的分类兜底组不参与合并；目标名如果和别的库重名会被拒绝，避免吞并别人的库。
35. **「刷新结果」挪到关联地址面板**：手动移除关联地址后要点它才会真正重查，原来放在顶部的导出按钮行，容易找不到。现在它在「关联地址」标题右侧，15px 加粗白字、深青渐变底、下沿 3px 实心投影做成凸起按键——鼠标按下时整体下沉 4px、投影压平并出现内阴影，手感明确。有手动移除时按钮文案变成「刷新结果（已移除 N）」并带一圈呼吸涟漪，提醒还有移除没生效；窄屏下自动占满一行。
36. **地址关联明细检索**：地址库页面顶部可以拿一个地址去比一整个地址库 / 标签组，列出它和库里哪些地址真的有转账（时间、方向、金额、区块、交易哈希）；也可以填两个地址直接查它们之间的转账，没有直连时顺着双方流水找中间地址，拼出 A → 中间 → … → B 的链路（「最多跳数」与关联层级同一上限，默认 3、最高 10；「翻页上限」同样 1–10）。本地索引与 Taostats 自动并用，每笔标注来源；受本机限速约束，预算用完会返回已查到的部分并提示可以接着查。
37. **启动脚本检测 Git 冲突标记**：从 GitHub 拉代码到另一台电脑时，如果合并冲突没解决，`start.ps1` 里残留的 `<<<<<<< HEAD` 会让 PowerShell 报「小于号是保留运算符」这种完全对不上号的语法错误。`启动.cmd` / `安装.cmd` 现在会先扫一遍同目录的 `*.ps1`，发现冲突标记就直接说明原因并给出修复命令。
38. **批处理脚本改用 GBK 编码**：修掉启动窗口里 `'…' is not recognized` 的乱码报错。根因是 cmd 在「UTF-8 批处理 + `chcp 65001`」下按字节偏移续读脚本，多字节汉字被读取边界切开就会错位，把注释行当命令执行。三个 `.cmd` 改成 GBK 并去掉 `chcp`，注释改为 ASCII 英文，中文提示照常。
39. 地址库支持**巡检自动入库**：定期检查库内地址的新转账（含子网 stake 代币转移），新对手方单笔或累计达到阈值（默认 30 TAO）就自动入库，按下累计金额最多的地址库归属，并写入可撤回的入库日志。
40. 扫描结果带**关联强度**（极强 / 强 / 中 / 弱）并按「交易所最前 → 强度 → 层级 → 金额」排序；本地索引每 5 分钟自动补扫新块。
41. 地址库支持“同步官方交易所地址”：官方名单默认导入（每次启动后台同步一次），同步**只增不改**并提示新增了哪个地址；官方来源的交易所判定固定、不可改判，只有人工判定的交易所才能改。同步使用 Taostats `GET /v1/exchange-addresses`，也可以手动添加或导入交易所/验证者地址。
42. **全站排版按字段宽度重排**：左侧导航固定不随页面滚动；扫描区起始地址拿最大宽度（48 位地址完整显示），层级/阈值/方向压成窄字段；表格列宽按内容分配、数字与状态居中，关联结果 9 列在 1440px 下不再横向滚动；主操作（扫描、同步、新建地址库、检索、巡检、补录）统一放大为实心渐变大按钮，表格里的复制/移除等小操作也提到 12px。
43. **地址库导出支持「全部 / 选中」，新增「公共地址」分类**：工具栏改成「格式 + 导出全部 + 导出选中 (N)」，勾选几条就只导出几条（没勾选时按钮禁用，不再出现“点了一下实际导出整库”）；关键地址除了「标为交易所」，还能「标为公共地址」——中转、发币池、公共充值地址这类汇聚型账号，查询时查到即作为关联终点、不再向下扩展（可再勾「过滤公共地址」连它本身也排除），排序排在交易所之后、其他地址之前。
44. **验证者地址同样终止关联，并支持一键同步验证者名单**：带 `VALIDATOR` 分类的地址（人工标记或官方名单同步）查询时查到即截止，不再展开下游，避免验证者押注/解押/质押流水把结果灌满无效关联。地址库工具栏在「同步官方交易所地址」旁边新增「同步验证者地址」（Taostats `GET /v1/validators/active`），只增不改、提示新增数量；人工核实过的交易所 5 个与验证者 1 个已作为**内置固定名单**随版本预置（`app/builtin_addresses.py`，每次启动幂等写入，来源显示「内置固定」），内置记录不能删除、不能改分类、不能改判。任意层级（含 1 级直达转账）都能点「路径明细」查看逐笔时间、区块与金额。
45. **确认之后回头校正旧结果**：交易所、验证者、公共地址都是关联终点，但以前的查询发生时它们还没被认定，旧结果里留着一整片下游噪音。现在只要「标为交易所 / 标为公共地址」、备注或标签写上「交易所」、改分类、同步官方名单，后端就会用和实时查询同一套口径重剪历史快照（优先看逐跳路径，路径缺了才退回中转图判断，没有确凿证据一律不删），地址库工具栏还提供「校正历史结果」按钮先预演再落库。巡检候选与自动入库流水里由终点地址触发的部分也会一并清理/撤回。实测把一条 199 个关联的旧查询剪到 9 条。
46. **起始地址画像：注册日期、质押次数、日均频次、余额**：这四项显示在**左侧栏导航下方的空白处**（不占用结果阅读宽度），四项按「标签在左、值在右」对齐，页面拉宽变窄都不影响结果表格。**地址只显示头 4 + 尾 4 位**（如 `5Hiv…N8kS`），鼠标悬停看完整地址，后面的「复制」按钮复制的仍是完整 48 位。指标口径：**注册日期**（Taostats `/api/account/latest/v1` 的 `created_on_date`，并标注注册网络）、**质押次数**（`/v1/subnets/stake-events` 的 `action=all` 的 `total_items`——**子网质押与解质押各算一次**，实测 `stake`+`unstake` 恰好等于 `all`，且不含质押转移；**本地索引模式也会走 API 取真实次数**——本地索引只有 `stake_transfer` 边，没有 `stake`/`unstake` 操作事件，数不出质押次数；只有完全没配 key 时才退回转账笔数并标注口径，此时不算日均频次）、**日均频次**（质押操作次数 ÷ 注册至今天数，当天按 1 天算）、**余额**（`balance_total`，副行拆出可用与质押；取不到时退回 RPC 可用余额）。四项共 **2 次** Taostats 请求（注册日期+余额 1 次、质押总量 1 次，都只读分页总量不翻页），共享 5 次/分钟本地限速与 5 分钟缓存；拿不到就显示「未获取」并说明原因，**绝不用 0 顶替、也不会让主查询失败**。窗口 ≤950px 时侧栏变成顶部横条，这块会自动搬回结果区顶部改成四列。

47. **预置验证者名单（离线可用）+ 地址库分页 + 同步接口方法兼容**：把一次同步下来的 1196 个活跃验证者地址随版本发布（`app/data/builtin_validators.txt`，一行一个地址），启动时幂等写进地址库并标为「内置固定」——**没有 API key、Taostats 不可达的机器也能直接拿到「查到即终止」的验证者终点集合**，不必先联网同步；名单要更新就改这个文件并升版本。地址库清单每组按 50 条分页（组标题仍显示整组条数，「全选本组」跨页生效，勾选翻页不丢），预置验证者无需把 1194 行一次铺开。另外 `/api/library/import-validators`、`/api/library/import-exchanges` 现在 GET / POST 都接受，动态行路由限定为整数——远端浏览器拿到 GET 请求时不会再被 `/api/library/{row_id}` 抢先匹配报 405 Method Not Allowed。扫描结果里的关联地址强制单行（只锁地址本身，操作按钮可换行），不再折成两行。
48. **升级后自动重启 + 环境自检**：以前 `git pull` 到新版本再双击「启动.cmd」，脚本探到同目录已有服务在跑就直接退出，**旧进程一直活着，新代码一行没跑**；而页脚版本号读的是磁盘 `VERSION` 文件，于是显示新版本、功能却是旧的——「预置验证者看不到」「同步照样 405」都由此而来。现在 `start.ps1` 会比对进程版本与磁盘版本，不一致就打印「运行中 X → 磁盘 Y」并自动停掉旧进程重新拉起；`/api/version` 新增 `running_version` / `stale`，页脚在不一致时显示「运行中版本：0.7.7（磁盘已是 0.7.8，需重启）」并在更新日志页顶部弹出横幅。同时新增**环境自检**（更新日志页顶部面板 / `GET /api/diagnose` / 命令行 `python run.py --doctor`），一次算清代码版本、预置名单文件（条数与修改时间）、落库情况（验证者分类数、预置标签数）、本次启动写入条数、API key 状态，未通过项直接给出可执行的处理动作。

49. **「质押次数」「日均频次」改按子网质押操作计数**：原来这两项统计的是普通转账笔数，现在改成**子网质押与解质押的操作次数**（`stake` + `unstake` 各算一次），数据来自 `GET /v1/subnets/stake-events?coldkey=<地址>&action=all&limit=1` 的 `pagination.total_items`（一次请求拿总量，不翻页，仍受 5 次/分钟本地限速和 5 分钟缓存约束）。口径已实测对齐：某地址 9,466 = 质押 5,302 + 解质押 4,164，另一地址 906 = 475 + 431，且 `action=all` 不含 `is_transfer=true` 的质押转移。指标副行显示「质押 + 解质押」，单位由「笔」改为「次」；本地索引模式没有质押事件，降级为转账笔数并标注「本地索引无质押事件，改为转账笔数」。
50. **起始地址画像移入左侧栏**：注册日期、质押次数、日均频次、余额从扫描结果顶部搬到左栏导航与状态之间的空白处，结果区不再被这一排指标占掉整行宽度。地址显示为头 4 + 尾 4（`5Hiv…N8kS`），完整值放在悬停提示里，右侧「复制」按钮复制完整地址并回显「已复制」；扫描结果副标题里的起始地址同样改成头尾 4 位。窗口 ≤950px（侧栏变横条）时整块自动搬回结果区顶部，改为四列 / 两列。
51. **扫描先查起始地址画像，左栏立刻显示**：点「扫描关联」后先单独请求 `POST /api/seed-profile`，2～3 秒把四项填进左栏（先显示「查询中…」，拿到数据立刻换真实数字），关联扫描在后台继续跑，结束后再渲染结果表。实测左栏在 5.5 秒填好、关联在 11.9 秒结束。画像固定花 2 次请求，这 2 次会从本轮 5 次额度里扣掉（`prefetched_requests`），不会 2+5=7 次撞本地限速；命中 5 分钟缓存则为 0 次、不扣。画像失败只是显示「未获取」并提示原因，扫描照常继续。
52. **路径明细一行一跳**：关联地址行展开的「路径明细」重排为固定窄列——「跳」44px、路径自适应（实测 632px）、流向/类型 118px、金额 104px、时间 150px、区块 88px，每跳行高从 62px 降到 34–35px，地址不再换行；「第 1 跳」改圆形徽标，「子网 stake 转移 · 子网 14」压成 `stake#14`，「对方转入/向外转出」压成彩色「转入/转出」标签。展开后的「收起明细」改为强调色实心按钮（78×30），超过 3 跳时底部再给一个收起入口；展开行加左侧竖条与浅底色，收起后复位。深灰主题按钮改用新增的 `--on-accent` 文字色（原来白字压在浅灰绿底上对比度只有 2.13）。
53. **路径明细的地址统一成头 4 + 尾 4**：明细里的地址原来单独用头6尾6（0.8.2 重排时想着「明细列宽更宽、方便比对」），导致同一屏里主表 `5GBn…iEUi`、明细 `5GBn2X…iEUi9K` 是两种长度，同一个地址看着像两个。现在 `pathAddr()` 直接复用 `shortAddr()`，全站只有一处截断规则；扫描关联结果与查询记录（历史回看）共用 `renderResult()` → `pathDetailRowHtml()`，改一处处处生效。完整地址仍在悬停提示与 Taostats 跳转链接里。

54. **地址库清单支持搜索与角色筛选，系统角色不再误入用户自建库（0.8.6）**：清单工具栏在「按地址库」下拉旁新增搜索框（匹配地址 / 名称 / 地址库 / 备注 / 角色，输入即筛）和角色筛选（公共地址 / 交易所 / 验证者），两者可叠加、命中数实时显示「N / 总数 条」。更关键的是修了数据归属 bug：手动「标为公共地址」时后端会清空该地址的 `book`、归入公共地址分组，不再挂在用户自建库（如 6NCK）下；「新建地址库并导入」、导出地址 TXT、关联结果筛选现在统一按 `{EXCHANGE, VALIDATOR, PUBLIC}` 排除系统角色——此前误用「系统」常量导致公共地址永远漏网——所以新建库会自动过滤掉交易所、验证者、公共地址。（详见 `CHANGELOG.md` 0.8.6 条目。）

55. **地址库清单地址改为头尾各 4 位掩码并带复制按钮（0.8.7）**：清单地址列不再显示完整 SS58（约 48 位、窄列里折成两行），统一用 `shortAddr()` 头 4 + 尾 4、中间省略（`5Gjq…Thor`），仍是可点开 Taostats 的链接，紧邻一个「复制」按钮（复制完整地址），整行不换行。与「地址关联明细检索」结果表口径一致；全站地址展示统一为头尾各 4 位、中间隐藏（有特殊要求时例外）。

56. **跨机同步包升级为带时间戳的「最后写入优先」合并（0.8.8）**：地址库导出 JSON/CSV 现在带 `created_at` / `updated_at`，`schema_version` 升到 2；导入时按 `updated_at` 做 LWW 合并——`book` 可被较新的空值清空（修复「公共地址在某台移出用户库后，另一台残留旧 book 清不掉」的污染滞留），`label`/`note` 取较新一方但空值不覆盖非空，`categories` 仍取并集、交易所锁定不变。无时间戳的旧包（纯 TXT / 老 CSV / v1 JSON）仍走保守合并、行为不变。配合 Tailscale 单一事实源或私有 git 同步包，即可实现家里/公司多机地址库快速对齐（详见 `使用说明.md` 的「多设备同步地址库」一节）。

## 快速开始

**普通用户（推荐，无需命令行）**

1. 解压项目文件夹到任意位置（路径建议不含空格和 `#`、`&` 等特殊字符）；
2. 双击 **`安装.cmd`**，等窗口打印“安装完成”（装过的话会逐项提示跳过，1–2 秒结束）；
3. 双击桌面上的 **“Bittensor 地址关联挖掘”** 快捷方式，浏览器会自动打开 <http://127.0.0.1:8766>。

安装脚本会自动检测 Python（3.10–3.13，缺失时优先用 `installers\` 里的安装包静默安装 3.12）、创建 `.venv`、安装依赖、建立 `data` 与 `logs` 目录、创建桌面快捷方式。所有步骤都是幂等的：已装好的部分自动跳过，重复双击不会重装；依赖是否完整通过模块导入、`pip check` 和 `requirements.txt` 指纹（记录在 `.venv\.setup-state.json`）三重判断。环境疑似损坏时可执行 `setup.ps1 -Force` 强制重建。完整操作步骤、界面说明和常见问题见 **[使用说明.md](使用说明.md)**，也可以直接双击 **`使用说明.html`** 离线阅读。

**日常启动与停止（已装好环境）**

```powershell
.\start.ps1              # 后台启动，默认 8766 端口
.\start.ps1 -Port 8777   # 手动指定端口
.\stop.ps1               # 停止服务
```

也可以直接双击 `启动.cmd` / `停止.cmd`。同一台电脑上放了两份副本（比如拷到 `D:\` 做测试）时，第二份启动会自动避开被占用的端口（8766 → 8767），并在窗口里提示实际端口；`启动.cmd 8777` 也可手动指定。同一台电脑的机器码不变，副本拷上 `license.key` 即可直接用，不需要重新授权。

**升级之后必须重启服务（0.7.8 起会自动重启）**：`git pull` 或覆盖新文件只改了磁盘上的代码，正在跑的进程还是旧的。0.7.8 起再双击一次 `启动.cmd` 就会自己发现「运行中版本 ≠ 磁盘版本」并重启；更早的版本需要先双击 `停止.cmd` 再启动。不确定是哪个版本在跑，用不着猜——执行 `python run.py --doctor`（或打开页面「更新日志 → 环境自检」）会直接把代码版本、预置名单文件、落库情况、按什么顺序处理全部列出来。

**从零手动部署（开发者）**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py --host 127.0.0.1 --port 8766
```

### 迁到另一台电脑

> 注意：0.6.0 起工具需要授权激活，授权与电脑绑定——拷到新电脑后要重新激活（新电脑激活页会显示新的机器码）。
>
> 只是**同一台电脑**换个磁盘/目录再放一份（自测用）不属于“迁移”：机器码不变，`license.key` 拷过去直接可用，也不用重装，副本会自动换端口启动。

整个文件夹可以直接复制，但 `.venv` 记录的是原电脑的路径，**不能直接复用**。在新电脑双击 `安装.cmd` 即可，脚本会检测失效环境并自动重建。如果新电脑上已经装过这个工具（环境完整），再点安装只会输出“环境已就绪：本次没有重复安装任何组件”，不会重装 Python 或依赖。

- 想保留地址库和历史记录：把 `data\` 一起复制；
- 想从空白开始：删掉 `data\`，启动时会自动重建空库；
- 把文件夹发给别人前，建议先删除 `data\`，里面有你查过的地址记录。

### 启用 Taostats 免费档

1. 注册并创建 key：打开 <https://taostats.io/zh/pro> 登录（免费档标价 $0），再进入 <https://taostats.io/zh/pro/api-keys> 新建项目并生成 key（通常只完整显示一次，生成后立即复制）；找不到入口时看官方图文步骤 <https://taostats.io/zh/docs/start-here/getting-started-with-taostats-api>。官方套餐页当前列出每分钟 5 API credits、每月 10,000 API credits，实际可用历史范围和单次端点 credit 消耗以账户控制台及 API 响应为准。
2. 打开工具首页，在“Taostats API key”密码框中粘贴 key，点击“保存 API key”。页面只显示是否已配置，不会回显已保存的内容。

页面提交的 key 会用 Windows DPAPI 加密保存在本机 `data\settings.json`（绑定当前用户，不上传、不回显），服务启动时自动装回内存，重启后不用重填；点击“清除”会同时删掉本机保存的 key。0.6.4 起，勾着 Taostats 数据源但没配置 key 时查询会被直接拒绝并提示，不再静默回退本地索引。`/api/overview` 返回 key 是否已配置和本机请求统计。Taostats 查询每次最多发起 5 个 API 请求，并在应用进程内将同一地址同一页缓存 5 分钟；本机统计会跨服务重启保留，但不等同 Taostats 账户 credits 余量。未配置 key、遇到服务端限流或查询超出本轮预算时，界面会保留已取得的结果并标为部分结果/不可用。

### 分轮续查（每分钟一轮，直到查完）

一次 5 次请求通常覆盖不了多层关联（层级越高越吃不消），因此勾选“自动分轮续查”（Taostats 数据源下默认开启）后，查询会变成一个后台作业：

- 第 1 轮立刻执行，之后每轮间隔约 62 秒（`BITTENSOR_JOB_INTERVAL_SECONDS`，默认 62 秒），本轮没用完的额度不会累积到下一轮。
- 每轮从上一轮没查完的队列继续：已查过的地址和分页不会重复请求，缓存命中的结果也会接着用。
- 页面实时显示轮次、累计请求数、待查请求数和下一轮倒计时，并同时给出“上一轮实际查询了什么”和“下一轮计划查询什么”（一级关联转账 / 一级子网转移 / 二级及更深转账 / 转账历史翻页 / 二级及更深子网转移），可以随时“停止续查”。
- 轮数是上限而不是固定次数：待查队列一旦清空就立即结束，不会为了凑满轮数继续发请求。连续 3 轮一次请求都没成功（例如被限流）时也会停止，避免空转。
- “停止续查”会立刻用已取得的记录合成部分结果：页面照常展示当前关联地址（含层级、金额、地址库命中），并说明完成了多少轮、还剩多少个转账明细 / 子网请求未查询。
- 队列清空后统一合成最终结果（关联地址、层级、金额、地址库命中、提示语）。
- 上限：默认 5 轮（≈25 次请求），可在页面“最多查询轮数”里手动调高（1–100，对应最多 5–500 次请求，如 12 轮 ≈ 60 次）；最多发现 150 个地址（3 级，`BITTENSOR_JOB_MAX_ADDRESSES`），层级更高时按「层级 × 50」放宽（10 级放宽到 500 个，`BITTENSOR_JOB_ADDRESSES_PER_DEPTH`）；触顶会停止并给出提示，可调高轮数后再次发起继续。
- 作业状态保存在服务进程内存，服务重启即丢失，需要重新发起。密钥无效等不会自愈的错误会立即结束作业，不会每分钟空转。限流或服务不可用是暂时性错误，被中断的请求会放回队列，下一轮重试而不是丢弃。
- “导出地址 TXT”把当前结果的关联地址按每行一个导出，支持按层级分级导出（全部 / 仅 1 级 … 仅 10 级，文件名带 `-dN` 标记）；地址库中已确认的交易所地址和验证者地址不会写入文件，疑似交易所（待确认）仍会保留，导出提示里会说明排除了多少个。查询记录页的导出同样支持分级（接口 `depth` 参数）。

接口：`POST /api/relations/jobs` 创建作业（参数同 `/api/relations`，可带 `round_interval_seconds`、`max_rounds`），`GET /api/relations/jobs/{id}` 查询进度与最终结果，`POST /api/relations/jobs/{id}/cancel` 停止续查并立即返回已取得的部分结果与剩余待查数量。不勾选时仍走原来的单轮 `/api/relations`。

**关联层级（0.8.3）**：`depth` 取值范围 1–10，默认 3。层级只决定从起始地址向下走几跳，单边门槛、累计门槛、交易所/验证者/公共地址/「系统」截止规则在每一级完全相同。上限定义在 `app/relation_config.py`（`MAX_RELATION_DEPTH` / `DEFAULT_RELATION_DEPTH`），`/api/overview` 会把它和上次保存的扫描阈值一起返回。

**扫描阈值本地保存（0.8.3）**：`GET /api/settings/scan-thresholds` 读取、`POST /api/settings/scan-thresholds` 写入（body `{"min_edge_tao": "10", "min_total_tao": "50"}`），存在本机 `data\settings.json` 的 `scan_thresholds` 字段，和 Taostats API key 同一文件、互不覆盖。层级调高时通常要一起抬高这两个门槛，保存后下次打开页面自动填回；非法值不会覆盖已保存的设置。

### 查询记录（历史结果）

连续查了多个地址、前面忘了导出，可以到左侧“查询记录”里找回：

- 每次关联查询结束都会写入 `relation_archives` 表：分轮作业保存最终结果，手动停止保存当前已取得的部分结果，单轮查询也会保存一份。
- 列表显示时间、发起地址、状态（已完成 / 已停止 / 失败）、关联地址数、地址库命中数、轮次与请求数；支持翻页、单条删除和清空记录，最多保留最近 500 条（总体积超过 200 MB 时也会淘汰最旧记录）。
- “查看结果”会回到扫描页并载入那次查询的完整结果，表格、层级筛选、导出 JSON / 地址 TXT 都可以继续用。
- “导出地址”按与当前结果相同的规则导出：每行一个地址，排除已确认的交易所地址和验证者地址；“导出 JSON”保存完整结果快照。
- “同步地址库”把该次结果的关联地址 + 发起地址去重写入地址库，已存在的地址跳过，不覆盖原有分类、标签和备注。

接口：`GET /api/relations/history?limit=&offset=`、`GET /api/relations/history/{id}`、`GET /api/relations/history/{id}/export?format=txt|json`、`DELETE /api/relations/history/{id}`、`DELETE /api/relations/history`（body `{"ids":[...]}`）、`POST /api/relations/history/clear`；同步用 `POST /api/relations/sync-library`（`seed`、`addresses`、`category`、`label`、`only_library_matched`）。

#### 旧记录能不能找回？

查询记录从 0.3.0 才开始落库，之前的结果只存在服务内存和页面变量里，刷新或重启即丢失，数据库和运行日志里都没有快照，**无法直接还原**。唯一的补救是“批量补录”：到查询记录页粘贴当时的起始地址（每行一个），按扫描页当前的深度、阈值、方向和数据源逐个重跑，结果会自动写入查询记录。批量内相同地址只跑一次，可随时停止；重跑结果可能因链上新增数据与当时略有差异。

如果页面提示“后台版本较旧”，请先重启应用；重启后直接在首页输入 key，不需要设置 PowerShell 环境变量。

如需在后台启动：

```powershell
.\start.ps1
```

日志保存在 `logs/`。停止服务：

```powershell
.\stop.ps1
```

## 地址库文件格式

TXT：每行一个地址，`#` 之后可写备注。TXT 导入的地址默认归为「其他」。

```text
5ColdkeyAddressHere # team treasury
```

CSV（导出地址库使用相同字段）：

```csv
address,label,category,note
5ColdkeyAddressHere,Team treasury,大V,verified source
```

应用导出的地址库 CSV 还会包含 `exchange_confirmed` 和 `exchange_rejected` 两列，用于迁移交易所人工判断；JSON 以 `addresses` 数组保存相同字段。

JSON：

```json
{
  "addresses": [
    {
      "address": "5ColdkeyAddressHere",
      "label": "Team treasury",
      "category": "大V",
      "note": "source and evidence"
    }
  ]
}
```

地址库分类：用户分类（大V / 群友 / 其他 / 系统 + 自建）记录地址身份，CSV/JSON 可以直接写入 `category`，也支持 `categories` 多分类字段（空格分隔），未知分类会自动登记进分类清单；一条地址可同时属于多个分类，主分类取第一个，地址库明细点“改分类”即可勾选调整。`EXCHANGE` 与 `VALIDATOR` 是系统分类，只由“确认交易所”操作或官方名单产生，用于过滤公共地址，旧文件里的 `WATCH` / `SEED` / `BLACKLIST` 导入时自动折算为「其他」。TXT 默认导入为「其他」。关联结果中的“疑似交易所（待确认）”可点击确认，确认后才进入交易所过滤集合。地址库页支持勾选多条记录后批量删除。地址库明细每行地址后都有“复制”按钮，地址库明细、关联结果与路径明细里的地址都可点击直接在 Taostats 账户页打开。标签没填时默认显示地址后四位（扫描同步用起始地址后四位，手动录入用该地址后四位）；改名是整组动作——组标题右侧「改名」会把这一组的地址一起换名，单条地址只维护备注。扫描结果命中地址库时，同步默认合并进命中的标签组（新地址去重加入，不另起新组），只有「新建地址库并导入」才创建新组；地址库清单的「撤回上次导入」可以删除上一次批量导入的地址并还原被改写的记录。同步官方交易所地址前，需要先在首页填写 Taostats API key；服务启动时会在后台自动同步一次（30 分钟内不重复），运行期间也可手动点按钮刷新。同步**只新增没见过的地址**：已在库里的地址保留原主分类、名称、备注与所属地址库，只把 `EXCHANGE` 追加进多分类并锁定判定；名单里消失的地址不会被删除。来源标记为 `taostats:/v1/exchange-addresses` 的记录判定固定，界面显示“官方交易所 · 不可改判”，接口也会拒绝改判、改分类与导入覆盖。

## 索引和查询口径

- 边：`Balances.Transfer`（普通 TAO 转账）与 `SubtensorModule.StakeTransferred`（两个不同 coldkey 之间的子网 stake 转移）。方向均为 `from → to`；两者金额都按 TAO 等值计价，前者是转账金额，后者是事件中的 TAO 等值，不是 alpha 数量。
- 第一跳：用于定位资金邻居，低额转账仅作为探索线索，不展示为保留边；关系仍需达到累计金额门槛。
- 第二、三跳：单边金额必须达到门槛，累计金额必须达到关系门槛。
- 共享对手方、相同时间、质押、解质押、购买、swap 和代理调用没有被自动当成资金关联；子网 stake 转移只以 `StakeTransferred` 事件纳入，两个 coldkey 相同的记录会跳过。
- 勾选 Taostats 时，查询只覆盖该 API key、Taostats 服务端分页窗口和本轮成功返回的记录；应用会标明请求分页是否完成。分页完成不等于数据源包含全链历史，也不代表账户计划未限制历史范围。
- 勾选 Taostats 时，本轮还会按地址查询 `/v1/subnets/stake-events` 的 `is_transfer` 记录；两类查询共用单次最多 5 次请求的预算。预算按关联价值排序消耗：一级关联转账 → 一级关联子网 stake 转移 → 更深层级转账 → 转账明细分页 → 更深层级子网转移；额度用尽时界面会列出未执行的请求数。该端点返回的对手方字段若缺失，对应记录会被跳过并提示，不会猜测方向。
- 余额查询（起始地址、关联地址、交易所候选）走本地 RPC，不消耗 Taostats 额度，但一律排在所有关联查询之后。本轮 5 次额度已全部用于关联查询时，只读取起始地址余额，跳过关联地址和交易所候选余额检查，并在页面提示。
- 截至 2026-11-01，Taostats 新版转账文档没有把 `/v1/transfers` 概括为“免费档只保留 7 天”。文档公开说明的是分页最多触达 1,000,000 行，超过范围要使用 `block_start/block_end` 或 `timestamp_start/timestamp_end`；因此一两个月没有交易的地址不能仅凭一次短窗口结果判断为交易所。免费计划的实际历史范围、每个端点 credits 消耗和账号权限仍以账户控制台与认证响应为准。
- 关闭 Taostats 时，查询只覆盖本地索引的转账记录，不代表全链历史。旧索引不会自动补采当时未纳入的子网事件，需要重新扫描对应区块区间。
- 一笔转账是行为证据，不是同一控制人、真实身份或共同受益人的证明。
- 已确认交易所地址只作为公共地址终点；“交易所关联疑似中转钱包”只表示当前查询数据中存在直接转账关系。当前查询数据包含 `Balances.Transfer` 与子网 stake 转移，仍未覆盖质押、解质押和购买等完整子网交易语义，不能证明该地址在全链历史中绝对没有子网交易。

## 历史数据限制

公开 RPC 的当前节点可以读取最新区块事件，但历史运行时状态会被裁剪。已验证超过一定区间后出现 `State already discarded`。因此：

- 短期增量分析：当前实现可以直接使用。
- 连续更新：按新区块顺序执行“扫描最新”或“继续水位”。
- 全历史深层追溯：须接入保留完整历史状态的归档节点，或可靠的第三方索引服务，并重新验证其历史完整性。
- 本工具不会将稀疏本地索引包装成完整历史结论。

## 发布文件说明

**给使用者**

- `安装.cmd`：一键安装（检测 Python、建 `.venv`、装依赖、建目录和桌面快捷方式）；可重复运行，已就绪的步骤自动跳过。
- `installers\`：离线安装素材 —— Python 3.12.10 官方安装包 + 项目依赖的 wheels（约 37 MB）。没有 Python 时脚本会自动静默安装，装依赖也优先走本地 wheels，**全程无需联网**。
- `启动.cmd` / `停止.cmd`：双击启动、停止本地服务。
- `查看机器码.cmd`：双击显示本机机器码（申请授权时用）。
- `签发授权.cmd`：管理员双击，按问答给团队成员的电脑签发授权码（需要项目上一级目录的 `.license-keys\` 私钥）。用法见 [授权管理.md](授权管理.md)。
- `使用说明.md` / `使用说明.html`：面向普通人的完整图文说明，HTML 可离线双击查看。
- `VERSION`：当前应用版本。
- `CHANGELOG.md`：版本变更记录。页面底部会显示当前版本号，点击“查看更新日志”可看各版本发布日期和功能变更。

**给开发者**

- `app/`：FastAPI 后端、关联算法、Taostats 客户端和前端页面。
- `app/seed_books/`：随包分发的预置地址库，每个 TXT 文件是一个标签组（文件名即组名），首次启动自动导入已知地址库。地址库里缺失时可在界面点「重新导入预置库」补齐（解散 / 误删后也能补回）。
- `tests/`：单元测试和 API 测试。
- `tools/build_usage_html.py`：由 `使用说明.md` 生成 `使用说明.html`（改完说明后运行一次）。
- `tools/make_release.py`：打外发包，生成 `Bittensor地址关联挖掘-<版本>-外发包.zip`（自动排除 `.venv`、`data`、`logs`、`license.key`、管理员与开发文件）；加 `--with-admin` 则连 `tools`、`docs`、`授权管理.md`、`签发授权.cmd` 一起打。
- `tools/issue_license.py`：授权码签发/校验工具（`--interactive` 即双击脚本走的问答模式）。
- `docs/HANDOFF.md`：中文开发交接和运行状态。
- `docs/DESIGN_FEASIBILITY.md`：技术方案和可行性边界。
- `docs/VERIFICATION.md`：实际测试与验收记录。

仓库只保存源代码和文档。`data/`、`logs/`、`.venv/`、Python 缓存和测试缓存已加入 `.gitignore`，避免把本地数据库、运行日志或用户地址库直接发布。

> **外发时不要直接右键压缩整个文件夹**：服务运行时 `data\wallet_link.db` 被 SQLite 占用，Windows 压缩会报“文件正由另一进程使用”然后失败；而且整目录里还有自己的查询记录和 `license.key`。用 `tools\make_release.py` 打包，它只装运行需要的文件（约 40 MB，已验证解压后可离线安装并启动）。
