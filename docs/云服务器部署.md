# 部署到云服务器

> **适用场景**：把服务从"某台常开的电脑"搬到云服务器（阿里云 / 腾讯云 / AWS 等 VPS），
> 让它 7×24 在线，家里、公司、手机随时打开。
>
> **先读结论**：能跑，但有 **4 个坑**必须先知道，否则搬到一半会卡住：
> 授权要重签、Taostats key 要重填（还可能明文落盘）、RPC 出口要能出去、
> 云厂商安全组要放行端口。**其中第 2 条和第 3 条最容易让人以为"搬坏了"。**

---

## 一、先做个决定：云服务器 vs 家里常开电脑

| | 云服务器 | 家里常开电脑 |
| --- | --- | --- |
| 在线时长 | ✅ 天然 7×24 | ⚠️ 停电/休眠就断 |
| 公网访问 | ✅ 自带公网 IP，不用隧道 | ❌ 要 Tailscale 或内网穿透 |
| 延迟 | ✅ 通常更好 | ⚠️ 上行带宽常是瓶颈 |
| 出站到 taostats.io | ⚠️ **看机房**，国内机房可能同样被墙 | ⚠️ 同样需要代理 |
| 数据安全 | ⚠️ 数据在别人机器上 | ✅ 数据在自己手里 |
| Taostats key 加密 | ❌ **Linux 上只能明文存** | ✅ Windows DPAPI 加密 |
| 成本 | 每月几十元起 | 电费 |

**如果你的数据比较敏感，或者只是自己用**，家里那台常开电脑 + Tailscale 往往更省心（见 `docs/固定主机迁移.md`）。云服务器的优势是"不用管电力、自带公网 IP"。

---

## 二、四个坑，逐个说清

### 坑 1：授权码要重新签发（必做）

授权是**一机一码**的（Windows 用 MachineGuid，Linux 用文件指纹派生）。

```bash
# 在新服务器上装好代码后，先取机器码
cd /opt/bittensor-wallet-link-intel
python3 -c "from app import license; print(license.machine_code())"
# 形如 ABCD-EFGH-JKLM-NPQR
```

把这个机器码发给持有私钥的人，用 `tools/issue_license.py` 签发新的授权码，粘回首页激活。

> **Linux 的机器码不稳定**：Windows 用 MachineGuid（重装系统才变），Linux 没有等价物，
> 代码退回到文件指纹（`/etc/machine-id` 等组合）。**换内核、重建实例、迁移可用区都可能变**，
> 变了就得重签。这一点在云上比在物理机上更常遇到。

### 坑 2：Taostats key 在 Linux 上是明文（重要）

Windows 下 key 用 DPAPI 加密，绑定当前用户，拷到别的机器解不开——**这是好事**。
Linux 没有 DPAPI，代码会**降级成明文**存进 `settings.json`：

```json
{ "taostats_api_key": { "enc": "plain", "value": "你的key明文" } }
```

**所以云服务器上必须做到**：

1. 文件权限收紧到只有服务用户可读：
   ```bash
   chmod 600 /opt/bittensor-wallet-link-intel/data/settings.json
   chown wallet:wallet /opt/bittensor-wallet-link-intel/data/settings.json
   ```
2. 不要把这个目录放进任何 git 仓库/网盘同步；
3. 不要和其他服务共用系统账号；
4. 如果 key 泄露过，去 Taostats 后台**吊销重发**，不要只改密码。

`GET /api/overview` 返回的 `taostats_key_storage` 会显示当前保存方式是 `dpapi` 还是 `plain`
（页面「Taostats API key」面板上也会显示），**看到 `plain` 就要按上面四条收紧权限**。

### 坑 3：出站到 taostats.io 不一定通

这是 0.8.16 踩过的老坑：国内直连 `taostats.io` 会超时，表现是"查询失败，提示没有 API key"——**其实是网络不通，被误报成没配 key**。

云服务器上先测：

```bash
curl -sS -o /dev/null -w "%{http_code} %{time_total}s\n" --max-time 15 https://api.taostats.io/v1/transfers
# 200 或 401 = 通了（401 表示没带 key，网络没问题）
# 000 / 超时 = 不通，要配代理
```

不通就配代理，用环境变量（最省事）：

```bash
export WALLET_LINK_HTTP_PROXY=http://127.0.0.1:7890
# 写进 systemd unit 的 Environment= 里，见第五节
```

> 注意：这里说的**只是服务端出站**。你在浏览器里打开 taostats.io 是另一回事，两者互不影响。

### 坑 4：云厂商安全组要放行

云服务器有**两层防火墙**，只改一层不够：

1. **厂商控制台的安全组**（阿里云/腾讯云的"安全组"、AWS 的 Security Group）——最容易忘；
2. 系统内 `ufw` / `firewalld`。

只放行你自己用的端口，**不要把 8766 直接开到公网**：

```bash
# 推荐：只允许你自己的固定 IP 访问
# 阿里云/腾讯云安全组规则：入方向 TCP 8766，源 = 你的公网 IP/32
```

**更要紧的是别裸奔**：服务虽然自带访问口令（`settings.json` → `access_token`），但把带口令的面板直接暴露在公网，等于把门锁挂在门上。**强烈建议只在 Tailscale / WireGuard 内网访问**（见第六节），公网只留 SSH。

## 三、安装步骤（Ubuntu 22.04 / Debian 12 为例）

### 3.1 装系统依赖

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git
# 编译 async-substrate-interface 相关依赖时可能需要
sudo apt install -y build-essential python3-dev
python3 --version   # 需要 3.10 以上，推荐 3.11/3.12
```

### 3.2 装代码

```bash
sudo useradd -r -m -d /opt/bittensor-wallet-link-intel -s /bin/bash wallet
sudo -u wallet git clone <你的仓库地址> /opt/bittensor-wallet-link-intel
cd /opt/bittensor-wallet-link-intel
```

没有仓库就手工上传整个文件夹（**不要**带 `.venv`、`data/*.bak_*`、`logs/`）。

### 3.3 建虚拟环境装依赖

```bash
sudo -u wallet python3 -m venv .venv
sudo -u wallet .venv/bin/pip install -U pip
sudo -u wallet .venv/bin/pip install -r requirements.txt
```

`requirements.txt` 里如果锁了 Windows 专用包（如 `pywin32`），先看一眼；那类包只在
`settings_store` 里用 `ctypes` 调用 DPAPI，Linux 下会自动跳过，通常不需要装。装不上就
从 `requirements.txt` 里注释掉它，代码本身有 `os.name != "nt"` 的保护。

### 3.4 搬数据

把 Windows 机器上的 `data/wallet_link.db` 和 `data/settings.json` 传上来：

```bash
# 在 Windows 上
scp data/wallet_link.db wallet@<server>:/opt/bittensor-wallet-link-intel/data/
scp data/settings.json wallet@<server>:/opt/bittensor-wallet-link-intel/data/

# 在服务器上收紧权限
sudo chown -R wallet:wallet /opt/bittensor-wallet-link-intel/data
chmod 700 /opt/bittensor-wallet-link-intel/data
chmod 600 /opt/bittensor-wallet-link-intel/data/settings.json
chmod 600 /opt/bittensor-wallet-link-intel/data/wallet_link.db
```

**本地索引跟着 `wallet_link.db` 一起走**（`transfers` 表就在里面），不用单独迁。迁移后
索引会落后一段，后台自动扫描会追平，详见 `docs/固定主机迁移.md` 的「2.3.1 本地索引怎么迁」。

**Taostats key 不要指望能解出来**：Windows 上用 DPAPI 加密的 key 到了 Linux 解不开
（`enc: dpapi` 会读不出值）。启动后到页面重新填一次 key，它会以 `plain` 方式存下来。

### 3.5 首次启动（前台试跑）

```bash
cd /opt/bittensor-wallet-link-intel
sudo -u wallet .venv/bin/python run.py --remote --port 8766
```

看到启动横幅（访问口令、本机/局域网地址）就说明起来了。另开一个终端验证：

```bash
curl -s http://127.0.0.1:8766/api/health
```

### 3.6 激活授权

打开 `http://<server-ip>:8766`，会提示未激活，页面会显示**当前机器码**。拿去签发后粘贴激活。

也可以命令行取机器码：

```bash
sudo -u wallet .venv/bin/python -c "from app import license; print(license.machine_code())"
```

## 四、跑在后台：systemd

别用 `nohup` 凑合，用 systemd：崩溃自动重启、开机自启、日志统一。

```ini
# /etc/systemd/system/bittensor-wallet.service
[Unit]
Description=Bittensor Wallet Link Intel
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=wallet
Group=wallet
WorkingDirectory=/opt/bittensor-wallet-link-intel
ExecStart=/opt/bittensor-wallet-link-intel/.venv/bin/python run.py --remote --port 8766
Restart=always
RestartSec=5
# 出站代理（坑 3）：需要时打开，换成你的代理地址
# Environment=WALLET_LINK_HTTP_PROXY=http://127.0.0.1:7890
Environment=PYTHONUTF8=1
StandardOutput=append:/opt/bittensor-wallet-link-intel/logs/service.log
StandardError=append:/opt/bittensor-wallet-link-intel/logs/service.err.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo mkdir -p /opt/bittensor-wallet-link-intel/logs
sudo chown wallet:wallet /opt/bittensor-wallet-link-intel/logs
sudo systemctl daemon-reload
sudo systemctl enable --now bittensor-wallet
sudo systemctl status bittensor-wallet
```

常用命令：

```bash
sudo systemctl restart bittensor-wallet   # 改完代码/配置后重启
sudo journalctl -u bittensor-wallet -f    # 跟日志
tail -f /opt/bittensor-wallet-link-intel/logs/service.err.log
```

> **改了代码必须重启**，只刷新浏览器不算（前端资源带版本号会自动重新加载，但后端进程还是旧的）。

## 五、对外访问：优先内网，别暴露公网

### 方案 A：Tailscale（推荐）

云服务器装 Tailscale 加入你的内网，设备间走 `100.x.x.x`，**不对公网开放 8766**。

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
tailscale ip -4          # 记下这个 100.x 地址
```

之后用 `http://100.x.x.x:8766` 访问，安全组里 8766 保持关闭。

### 方案 B：只放行自己的 IP

不想装 Tailscale，就在安全组里把 8766 的源限制成你的固定公网 IP。
手机流量、换网络时 IP 会变，需要回来改规则——这是它的代价。

### 方案 C：Nginx 反代 + HTTPS（要域名时）

```nginx
server {
    listen 443 ssl;
    server_name wallet.example.com;
    ssl_certificate     /etc/letsencrypt/live/wallet.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/wallet.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8766;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

**反代后要额外注意来源 IP**：服务判断"是不是本机"靠对端地址。走反代后所有请求
对端都是 `127.0.0.1`，会被当成本机而**跳过访问口令**。所以：

- 用 Nginx 时，**不要**把 8766 暴露到公网，只让 Nginx 从本机连；
- 并在 Nginx 里加一层 Basic Auth 或 IP 白名单，别只依赖面板自己的口令。

> 服务端对 `CF-Connecting-IP` / `X-Forwarded-For` 的采信有严格前提（仅当 TCP 对端是回环），
> 这是为了防止隧道场景下被人伪造头绕过口令。反代属于同一类场景，务必自己在外层加防护。

## 六、上云后要改的几个默认值

| 设置 | 位置 | 建议 |
| --- | --- | --- |
| 巡检开关 | 页面「地址库巡检」 | 上云后可以打开（服务器常开，正适合跑巡检） |
| 每 30 秒推进 | 同上 | 额度 5 时填 0（自动=1 个）；额度 60 可填 5~10 |
| 每日请求上限 | 同上 | 按你的套餐定，别一上手就 1000 |
| 本机自动扫描 | 无需配置 | 后台每 5 分钟扫 75 块，只走链上 RPC，不消耗 Taostats 额度 |
| 访问口令 | `data/settings.json` → `access_token` | 搬过去后建议**重置一次**（旧口令可能已在聊天记录/截图里） |

## 七、迁移后的自检清单

```bash
# 1. 服务在跑
curl -s http://127.0.0.1:8766/api/health
#    看 version 是不是你期望的版本

# 2. 授权有效（licensed: true）
curl -s http://127.0.0.1:8766/api/health

# 3. 数据在 + key 保存方式（taostats_key_storage 若是 plain 见坑 2）
curl -s http://127.0.0.1:8766/api/overview

# 4. 出站通（坑 3）
curl -sS -o /dev/null -w "%{http_code}\n" --max-time 15 https://api.taostats.io/v1/transfers

# 5. 跑一次真实查询，确认不是 500
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:8766/api/relations \
  -H "Content-Type: application/json" \
  -d '{"seed":"5DceuTr7XPqw67PNHW9ewzzo2cZ7Cm8HgfjwUqEpd8Mh8QNg","depth":1,"data_source":"local","min_edge_tao":"0","min_total_tao":"0"}'
```

五项都对，就可以把旧机器停掉。**别忘了停旧机器上的服务**——同一把 key 两台机器同时跑巡检，
会各以为自己 5 次/分钟没问题，服务端看到的是双倍，直接 429。

## 八、常见问题

**Q：Linux 上 `pip install` 卡在某个包编译失败？**
多半是 `async-substrate-interface` 的依赖要 Rust 或 C 工具链。先 `apt install build-essential python3-dev`；
还不行就去看那个包的 README 装对应工具。实在装不上，可以用 Docker 镜像跑，把 `data/` 挂载进去。

**Q：起来后页面能打开，但一点查询就 500？**
先看日志尾部：`tail -40 logs/service.err.log`。FastAPI 的异常栈就在那，最后几行通常是
`XXXError`，比猜快得多。

**Q：机器码变了，授权失效？**
Linux 的机器码来自文件指纹，重建实例/换内核可能变。重新取机器码 → 重签 → 重新激活。
如果经常变，考虑把服务固化在容器里并固定 `/etc/machine-id`（副作用自负）。

**Q：能不能用 Docker？**
可以，思路是：镜像里装好环境 → 把 `data/` 目录挂载进容器 → 端口映射 `8766`。
注意 `data/settings.json` 的权限、以及容器内时区（巡检按 UTC 算日界，界面显示北京时间）。

**Q：Windows 服务器可以吗？**
可以，而且**更安全**——DPAPI 能用，key 是加密的。直接用 `安装.cmd` + `start.ps1` 那一套，
再按 `docs/固定主机迁移.md` 配开机自启即可。**除非你特别需要 Linux，Windows 服务器更省事。**
