## 〇、合并工具硬规则（1.0.0）

1. **主次关系**：本工具以地址关联挖掘为主，事件监控是左侧栏独立入口和辅助证据面板；不得反过来把主界面改成事件监控布局。
2. **统一入口**：默认只启动 `8766` 主服务。事件监控通过 `/event-monitor` 页面、`/event-api/*` 内部代理和 `/static/event-monitor/*` 静态资源接入，不单独向局域网或公网开放事件端口。
3. **分库口径**：地址库、转账索引和扫描记录在 `data/wallet_link.db`；事件、GitHub、子网档案和事件监控确认名单在 `data/event_monitor.db`。两者不得重新合并成同一个 SQLite 文件。
4. **共享地址资料**：事件监控从主服务 `GET /api/event-monitor/library` 读取已知地址库；共享的是地址资料，不是监控状态。该接口只返回已归入命名地址库的地址，并返回未归档地址数量。
5. **监控对象是地址库**：事件监控名单默认为空，选择器以命名地址库为一级对象。一级勾选代表整库；展开后可二级勾选，只监控库内部分地址。单地址监控必须先在主工具建立单地址地址库。
6. **搜索口径**：搜索框优先匹配地址库名；输入地址后 4 位时必须反查所属地址库并展示该库。未归入命名地址库的散地址不得直接进入监控候选。
7. **删除边界**：事件监控页的「移出监控」只能删除事件监控确认记录，不得删除主工具 `address_library` 中的地址。
8. **旧库迁移**：迁移旧 `Bittensor_event/data/events.db` 时保留事件历史，默认清空旧监控名单；确需保留旧名单必须显式加 `--keep-watchlist`。
9. **依赖唯一**：事件链上采集复用项目现有 `async-substrate-interface`，禁止重新引入 `substrate-interface` / `scalecodec`，否则会与 `cyscale` 命名空间冲突并导致主工具无法启动。
10. **路由缓存**：事件页面或事件静态资源变更时，必须同步更新 `app/static/event-monitor/index.html`、`floating.html` 中所有 `?v=` 与主 `VERSION`；主页面 `styles.css` / `app.js` 继续按原有三处版本规则同步。事件前端只保留 `app/static/event-monitor/` 一份，禁止恢复 `app/event_monitor/static/` 旧副本。
11. **UI 边界**：事件监控嵌入区必须保留主侧栏；移动端不得出现横向页面溢出、可见横向滚动条、弹窗标题裁切或按钮遮挡。
12. **主题同步**：事件页面必须读取主工具 `wallet-link-theme`，实时支持跟随系统、暖色护眼和深灰护眼；事件卡片、输入框、弹窗、浮层和正文背景不得固定为白色。
13. **共享主链**：事件采集和地址自动入库必须共用同一 `SharedChainGateway` / WebSocket。事件请求使用 `PRIORITY_EVENT`，地址自动入库使用 `PRIORITY_NORMAL`，不得各自另开主链连接抢带宽。
14. **档案继承**：事件库首次启动优先从旧 `Bittensor_event/data/events.db` 继承 `subnet_profiles`、`subnet_profile_archive`、`repositories` 和 `subnet_trading_state`；目标已有数据时不得覆盖。
15. **项目方库默认预选、可取消（1.0.29 上限改 160）**：项目方（`SN1`–`SN160` 命名）地址库**不再由后端强制写入监控名单**——`seed_default_subnet_watch` 的默认开关关闭。改为在「选择地址库」弹窗打开时，把 `SN1`–`SN160` 命名库（整库，按库名判定，与后端 `SUBNET_BOOK` 一致）中尚未监控的地址**默认勾选为预选状态**，用户可取消任意库或库内地址后再点「确认加入监控」。取消的地址不会被加入监控，也不会被自动同步 / 重启重新加回（尊重 `watched_address_exclusions`）。「一键清除」必须真正清空所有待加入勾选；全库已监控的库用文字/样式表达，**不得**用 checkbox 的 checked 状态表示，否则清除后仍显示一片勾选、用户误以为没生效。子网编号上限以 `default_watch.MAX_DEFAULT_SUBNET` 为准（1.0.29 起为 160），改上限要同步改前端 `subnetBookNumber` 判断、规则第 22 条和所有测试。这条取代旧的「首次升级后端强制 seed 全部 SN 库」口径；旧实现保留为可被设置显式开启的可选路径，但默认是关的，避免把用户的取消操作冲掉。
16. **项目方事件尾注**：`SN1`–`SN160` 地址库表示对应子网项目方（1.0.29 起上限从 127 提高到 160，与默认监控预选范围一致）。命中这些地址的普通转账、质押/解质押、代币转移和冷键交换，必须在摘要末尾显示结构化 `project_owner_tags` 和醒目的 `（SNx项目方）`；事件列表、详情、浮窗和补全后的摘要都必须保留。
17. **非项目方规则不变**：其他地址库不得追加项目方尾注，只按原规则在事件前方显示交易发生子网。不得把交易发生子网误当成地址所属项目方。
18. **自动入库同步**：`WatchService.sweep_local_index()` 每轮返回 `address_rows`。主服务只能把这些新增或改判地址同步到事件监控中已确认且至少有一个启用地址的地址库；未监控库不得自动开启。
19. **同步不复活**：用户从事件监控删除地址时写入 `watched_address_exclusions`；自动同步和默认 seeding 必须尊重排除表。只有用户通过事件监控 API 显式重新添加时，才可解除排除。
20. **全局尘埃转账阈值**：普通 TAO 转账默认达到 **5 TAO** 才进入事件流；阈值是全局设置，不得恢复逐地址阈值。链上采集、地址模拟和事件流历史查询必须共用同一阈值，填 `0` 才关闭过滤。历史尘埃只隐藏、不删除；规则只过滤普通转账，不得误伤质押/解质押。
21. **事件监控地址库 UX**：地址库按 SN 数字升序，跳号只表示该子网暂无库；默认折叠；每页支持 10/50/100 个库，必须有首页、上一页、下一页、末页和页码跳转。每个库必须支持“移出整库”，批量删除只写事件监控排除表，不得删除共享已知地址库。批量全选必须先确认库数和地址数。普通转账不得使用黑色/深色文字底纹，统一使用主题蓝色字体，浮窗同样生效。
22. **当前 SubnetOwner 优先**：链上当前 `SubnetOwner` 是唯一官方身份。若地址已存在于普通或自动库，项目方同步必须把它迁入对应 `SNx 项目方` 库，并记录重归属；不得只记冲突后留下空项目方台账。原普通库其他地址不得受影响。只有同一 Owner 同时归属多个项目方子网时才保留冲突提示。 官方地址文字必须使用固定实色深紫 `#4c1d95` 并加粗，不得随主题回退成浅紫，也不得使用发光阴影或渐变。
23. **质押转移识别**：`StakeRemoved` 只有在区块、转出地址、热键、子网和金额与本地 `stake_transfer` 精确匹配时，才可派生目标钱包的 `StakeAdded` 买入事件。源项目方必须保留红色“解质押/卖出”，目标新钱包必须显示绿色“质押/买入”，一条卖出、一条买入，不得合并成单条记录；匹配不到不得猜测，仍只按正常“解质押”处理。项目方 Owner 转出的接收地址不受普通 30 TAO 门槛限制，必须自动归入同一项目方库，并同步到已监控的项目方地址库。
24. **子网注销/注册即时联动**：检测到 `NetworkRemoved` 后必须立即归档该 NETUID，整库删除所有同编号 `SNx` 地址库，并同步移除事件监控旧地址；检测到同编号 `NetworkAdded` 后必须立即读取新 Owner、创建新地址库，并在原库此前处于监控状态时恢复新 Owner 监控。生命周期事件必须串行后台处理，不阻塞链采集，且不受子网普通事件禁用开关影响。手动“同步项目方地址”完成后也必须自动对账事件监控，并在已监控 NETUID 发生 Owner 变更时恢复新 Owner。检测到 `SubnetIdentitySet` 时必须立即重新读取当前名称并更新地址库；链上名称为空时只能使用 NETUID 兜底名，不得伪造正式名称。

## 一、通用表达与事实口径（用户全局要求）

1. **事实优先**：以公开可验证信息为依据，不确定就明说，不编造。
2. **引用规范**：外部信息标注来源，统一用 MLA 格式；其余用自己的话重写。
3. **表达完整**：逻辑清晰，每句有明确主语，结构完整，兼顾专业与口语。
4. **区分事实与推测**：明确标注哪些是代码/资料里核实的事实、哪些是推断；无法验证的不写进结论。
5. **严格执行**：以上规则对任何问题都生效，不为凑答案而编造。
6. **投研分析用大白话解释清楚**；涉及 Bittensor 投研必须覆盖团队背景、项目内容、当前进度、商业前景、收入/回购、社区观点、后续跟踪、结论。
7. **编程项目更新完上传 GitHub，说明文档和版本号都要及时同步更新。**

## 二、交付流程（每次改动必做，顺序固定）

1. **增量改**：不重写架构、不动 license 逻辑、不动「交易所 / 验证者 / 公共地址作为关联终点」的规则。
2. **改静态资源必须同步升三处**：`VERSION`、`app/templates/index.html` 的 `styles.css?v=` 与 `app.js?v=`。漏一处浏览器会拿旧缓存，页脚版本却是新的。
3. **CHANGELOG 条目格式**：`## <版本> · <标题> · <日期>`，标题内不得出现第二个 `·`。首条即当前版本，`read_version_info()` 与 `test_version.py` 会校验。
4. **每个修复配一条回归测试**，光改代码不加测试不算完成。契约扩展时同步更新旧断言（不是放宽断言），并在测试里写明原因。
5. **测试命令用裸 `pytest`**（或 `.venv/Scripts/python -m pytest`）。brief 里带 `--basetemp` 的命令会 `FileNotFoundError`，不要用。跑完在 CHANGELOG 里写全量通过数。
6. **文档同步**：`README.md`（版本徽标 + 已实现清单 + 索引口径 + 接口说明）、`使用说明.md`、`使用说明.html` 三处都要跟着改；测试里应有静态断言防止漏改。
7. **git commit 并 push 到** `https://github.com/lmjs3256-hue/Bittensor_dizhiguanlian_wajue`。
8. 改完前端可用 `node --check app/static/app.js` 先验语法；改完 Python 用 `compileall -q app`。

## 三、项目硬约束（违反会出真事故）

- **地址显示**：所有地址统一 `shortAddr()` 头 4 + 尾 4 掩码（如 `5Gjq…Thor`），后带「复制」按钮复制完整地址。仅用户明确说「有特殊要求」时才显示完整地址。适用于地址库清单、关联结果、检索等所有展示处。（2026-11-07）
- **服务**：默认 `127.0.0.1:8766`；静态文件从磁盘读，改完刷新即可；版本不一致时页脚提示需重启。
- **跨机同步（甲方案，已定）**：一台常开主机跑服务，其余设备只当浏览器客户端（Tailscale / 局域网），传输走私有 git。
  - `run.py --remote` 或 `启动-远程访问.cmd` → 绑 `0.0.0.0` + 访问口令。**默认只监听 127.0.0.1 时整套校验跳过**，本机用法不变——改这块务必保住这条。
  - **禁止**「两台各跑一份 + 同步地址库」：`taostats._reserve_request()` 是进程级限速，两台共用一把 key 会超 10 次/分钟直接 429；同一把 key 同一时刻只能一台开巡检。
  - 同步包（JSON/CSV，`schema_version=2`）只用于迁移 / 重装恢复 / 备机离线回灌，导入按 `updated_at` 做 LWW 合并。**SQLite 绝不走网络文件系统共享，git 绝不同步 `.db`**。
- **PowerShell 脚本**必须保持 UTF-8 **BOM**；读 UTF-8 日志要显式 `-Encoding UTF8`（默认按 GBK 会乱码）。
- **污染整理（0.8.9）**：`self.categories()` 会把记录里出现过的分类名视为合法以保护旧 CSV 分类，故**不要据此重置主分类**；判定污染只看「有效分类集合」。
- **地址库台账**：`import_rows()` 必须登记 `book` 到台账（0.9.6），否则界面看得到库、同步却报「目标地址库不存在」。
- **子网项目方地址（0.9.9）**：项目方地址必须按 NETUID 写入 `subnet_owner_entries`，地址库库名为 `SN<编号> <子网名称>`，备注必须包含子网名称和项目方身份。数据只读 `NetworksAdded` / `SubnetOwner` / `SubnetIdentitiesV3`；启动检查一次、每小时判断是否满 7 天，手动按钮可立即同步。`NetworksAdded=false` 自动归档并从默认地址库视图隐藏；同 NETUID 再次注册必须复用原台账并按新名称、新地址恢复，不能把新旧项目合并成一个库。
- **自动入库多级传播（0.9.10）**：刚自动入库的地址必须立刻加入本轮已知集合，使后续 B→C、C→D 可按事件顺序继续传播；历史旧事件不回扫。自动入库游标必须保存 `(last_block, last_event_index)`，禁止退回只用区块号，否则 4,000 行截断会漏同一区块剩余事件。关闭自动入库必须继续推进复合游标；待达标候选必须排除已入库地址；地址库改名/合并/解散必须同步候选、日志和库间统计引用。
- **子网项目方重注册清理（0.9.11）**：同一 NETUID 快速重注册时，旧项目方记录必须物理移出原 `SN<编号>` 地址库，只保留 `SubnetOwnerEntry` 的归档台账；同步结果必须列出具体子网和新旧项目方地址。
- **子网注销/重注册整库清理（0.9.12）**：任一 NETUID 注销、身份变化或快速重注册时，原 `SN<编号>` 项目方地址库中的**所有地址**必须整库物理删除，禁止只删项目方一条；同时删除旧库台账、自动入库候选、库间统计，并撤回旧库产生的活跃自动入库日志。当前身份未变时保留当前库，只清理其他历史遗留同编号旧库。提示必须包含子网编号、名称、新旧项目方地址和清理地址数。

## 四、关联扫描的金额口径（0.9.8 起，本次对话新增）

**三把尺，各管一段，缺一不可**：

| 字段 | 页面标签 | 作用范围 | 出厂值 |
| --- | --- | --- | --- |
| `min_direct_tao` | 1 级关联最低 TAO | 起始地址直连的**那一笔**转账，按单笔判断、不累计 | `0`（不限金额，旧行为） |
| `min_edge_tao` | 单边最低 TAO | 第 2 跳及更深的单笔转账 | `1` |
| `min_total_tao` | 累计最低 TAO | 每个关联地址所有有效边的金额合计 | `1` |

- 口径唯一由 `LinkPolicy.edge_floor(depth)` 决定（`depth == 0` 用 `min_direct_tao`，其余用 `min_edge_tao`）；`relation.discover()` 与 `crawl.py` 两处都必须调它，**不许再各写一套 `depth == 0` / `current_depth > 0` 的豁免判断**。0.9.7 及以前的三处豁免正是「1 级不限金额、小额蹭关联」的根因。
- 低于对应门槛的转账：既不成为保留边，也不把对手方带进 BFS / Taostats 爬取队列，其下游整条线索随之消失。
- `min_total_tao` 的合计包含该地址作为中转点的下游边，**不能单独用来防蹭关联**（灰尘直连可被自己别处的大额往来撑过门槛）。
- 前端结果表的「金额筛选」只影响显示 / 建库 / 导出，不重新查询、不写进 `policy`；写文档和提示语时必须与三把尺分开说明。
- 三把尺一起落盘到 `data/settings.json` 的 `scan_thresholds`；**空输入框不提交该字段**，后端省略即保持上次保存值（0.9.7 及以前空值被硬塞成 `"1"`，会冲掉用户已保存的设置）。
- 新增 `LinkPolicy` 字段一律**追加到字段末尾**：历史代码有 `LinkPolicy(Decimal("1"), Decimal("0.1"))` 这种位置参数写法，插在中间会静默改掉 `min_total_tao`。
- 门槛只提高蹭关联成本，不是身份判定；彻底排除用「移除关联」（0.9.5 起落库、全机共享）或标为公共地址。

## 五、待用户确认的默认策略（不自行变更）

1. 发现两条规则打架（例如「增量改」与「全盘修复缺陷」边界不清），**先停下手里的实现**，把冲突点、两种做法的后果写清楚反馈给用户。
2. 用户确认后，把结论写进本文件对应章节，并同步到 `.workbuddy/memory/MEMORY.md`。
3. 后续任务以本文件为准；本文件与聊天里的临时口径冲突时，以本文件为准并要求用户确认是否更新。
25. **地址扫描响应性**：起始地址画像只能并行更新侧栏，不得阻塞扫描任务创建和队列状态展示。Taostats 传输层连续失败后必须进入短时熔断并快速返回明确错误，禁止每个请求重复完整长超时；成功请求后自动解除熔断。
26. **子网排放监控**：每 5 秒读取 `SubtensorModule.SubnetEmissionEnabled`，开启→关闭和关闭→开启都必须创建“排放开关”事件并实时推送。排放状态必须持久化，功能页同时显示交易开关和排放开关；不得用交易开关代替排放开关。
27. **排放模拟信号**：模拟信号目录必须提供“子网排放开启”和“子网排放关闭”两项，事件类型均为“排放开关”，事件名称均为 `SubtensorModule.SubnetEmissionEnabled`；摘要必须明确标注模拟及开启/关闭方向。
28. **分钱包主地址与即时解析**：StakeAdded/StakeRemoved 事件中冷键地址优先级必须高于项目方热键；买入主地址必须是目标冷键。StakeRemoved 到达时应从同区块 `transfer_stake` extrinsic（含 Proxy/RuntimeCall）即时解析 destination_coldkey，不得依赖延迟的本地索引；历史错误主地址必须自动修正。
29. **起始地址画像独立状态**：扫描结果中的空画像不得覆盖已经成功取得的同地址画像。画像必须按地址缓存，失败时保留上次成功值。左侧必须提供“查询画像”按钮，只调用画像接口，不创建关联扫描任务。
30. **画像卡片地址可见性**：“查询画像”按钮放在卡片标题行，不得与地址和复制按钮同排。地址行必须为 `头4…尾4` 显示保留固定宽度，后四位不得被省略或遮挡。
31. **自动入库设置编辑保护**：地址库页状态轮询不得覆盖用户正在编辑的阈值、候选天数、自动入库和流水线开关。编辑后必须进入待保存状态，保存成功后按服务端返回值回填，失败时保留输入。阈值空值或非法值必须明确报错，禁止用 `|| 30` 静默回落。
32. **自动入库默认阈值**：自动入库出厂阈值固定为 **15 TAO**；后端默认配置、主页面输入框、前端缺省兜底、接口说明和用户文档必须保持一致。旧设置文件中未改动的 30 TAO 阈值在升级时一次性迁移为 15 TAO，并写入默认版本标记；迁移完成后用户主动选择 30 TAO 必须保留，不得反复覆盖。
33. **监控名单保存设置与保持清空**：「选择地址库」弹窗的勾选表示「保存后要监控」的目标状态；全选 / 一键清除只改勾选，必须点「保存设置」才写入 `watched_addresses`。空勾选保存 = 移出全部监控地址并置锁定状态 `watch:address-list-lock`；全选保存 = 按勾选重建名单并解锁。锁定后所有加回入口（含 `clear_exclusion=True` 的项目方恢复、默认 seed、手动新增）必须被 `add_watched_address` 统一拒绝；锁定期间事件列表、详情与 SSE 均隐藏 `source=address` 事件，但历史记录不得删除，解锁后仍可见。已保持清空时弹窗不得默认预选项目方库。
34. **后端改动必须重启服务才生效**：静态资源从磁盘读、刷新即可；但 `server.py` / `storage.py` / `main.py` 等后端代码在服务启动时加载进内存，新增接口改完只刷新浏览器会报「接口不存在」（1.0.30 实测踩坑）。交付涉及后端改动时，必须重启服务并用真实 HTTP 请求验证新路由返回非 404。验证会写库的接口（如空勾选保存会清空并锁定名单）时，优先用非法参数触发 400 来证明路由存在，避免污染用户数据；若不慎写入，必须把 `collector_state` 里对应的状态记录删掉还原。
