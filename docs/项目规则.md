# 项目规则（Bittensor 地址关联挖掘工具）

> 本文件是**本项目的执行规则清单**，来源为历次人工对话里明确提出的约定与项目 brief。
> 后续任务默认按本文件执行；规则之间若出现冲突，**先反馈给用户确认，确认后再改本文件**，
> 不自作主张二选一，也不在两个地方各留一套说法。

最后更新：2026-11-13（0.9.8）

---

## 一、通用表达与事实口径（用户全局要求）

1. **事实优先**：以公开可验证信息为依据，不确定就明说，不编造。
2. **引用规范**：外部信息标注来源，统一用 MLA 格式；其余用自己的话重写。
3. **表达完整**：逻辑清晰，每句有明确主语，结构完整，兼顾专业与口语。
4. **区分事实与推测**：明确标注哪些是代码/资料里核实的事实、哪些是推断；无法验证的不写进结论。
5. **严格执行**：以上规则对任何问题都生效，不为凑答案而编造。
6. **投研分析用大白话解释清楚**；涉及 Bittensor 投研必须覆盖团队背景、项目内容、当前进度、商业前景、收入/回购、社区观点、后续跟踪、结论。
7. **编程项目更新完上传 GitHub，说明文档和版本号都要及时同步更新。**
8. **每个项目的人工对话要求单独整理成规则文档**（即本文件），避免同一问题反复纠正；发现规则冲突马上反馈确认，确认完毕更改本文件，后续默认按本文件执行。
9. **主动全盘排查代码逻辑缺陷**：不能每次等用户提一点改一点、又把前面的问题暴露出来。发现缺陷要一次性提出完善建议并评估连锁影响。

## 二、交付流程（每次改动必做，顺序固定）

1. **增量改**：不重写架构、不动 license 逻辑、不动「交易所 / 验证者 / 公共地址作为关联终点」的规则。
2. **改静态资源必须同步升三处**：`VERSION`、`app/templates/index.html` 的 `styles.css?v=` 与 `app.js?v=`。漏一处浏览器会拿旧缓存，页脚版本却是新的。
3. **CHANGELOG 条目格式**：`## <版本> · <标题> · <日期>`，标题内不得出现第二个 `·`。首条即当前版本，`read_version_info()` 与 `test_version.py` 会校验。
4. **每个修复配一条回归测试**，光改代码不加测试不算完成。契约扩展时同步更新旧断言（不是放宽断言），并在测试里写明原因。
5. **测试命令用裸 `pytest`**（或 `.venv/Scripts/python -m pytest`）。brief 里带 `--basetemp` 的命令会 `FileNotFoundError`，不要用。跑完在 CHANGELOG 里写全量通过数。
6. **文档同步**：`README.md`（版本徽标 + 已实现清单 + 索引口径 + 接口说明）、`使用说明.md`、`使用说明.html` 三处都要跟着改；测试里应有静态断言防止漏改。
7. **git commit 并 push 到** `https://github.com/lmjs3256-hue/Bittensor_dizhiguanlian_wajue`。
8. 改完前端可用 `node --check app/static/app.js` 先验语法；改完 Python 用 `compileall -q app`。

## 三、项目硬约束（违反会出真事故）

- **地址显示**：所有地址统一 `shortAddr()` 头 4 + 尾 4 掩码（如 `5Gjq…Thor`），后带「复制」按钮复制完整地址。仅用户明确说「有特殊要求」时才显示完整地址。适用于地址库清单、关联结果、检索等所有展示处。（2026-11-07）
- **服务**：默认 `127.0.0.1:8766`；静态文件从磁盘读，改完刷新即可；版本不一致时页脚提示需重启。
- **跨机同步（甲方案，已定）**：一台常开主机跑服务，其余设备只当浏览器客户端（Tailscale / 局域网），传输走私有 git。
  - `run.py --remote` 或 `启动-远程访问.cmd` → 绑 `0.0.0.0` + 访问口令。**默认只监听 127.0.0.1 时整套校验跳过**，本机用法不变——改这块务必保住这条。
  - **禁止**「两台各跑一份 + 同步地址库」：`taostats._reserve_request()` 是进程级限速，两台共用一把 key 会超 10 次/分钟直接 429；同一把 key 同一时刻只能一台开巡检。
  - 同步包（JSON/CSV，`schema_version=2`）只用于迁移 / 重装恢复 / 备机离线回灌，导入按 `updated_at` 做 LWW 合并。**SQLite 绝不走网络文件系统共享，git 绝不同步 `.db`**。
- **PowerShell 脚本**必须保持 UTF-8 **BOM**；读 UTF-8 日志要显式 `-Encoding UTF8`（默认按 GBK 会乱码）。
- **污染整理（0.8.9）**：`self.categories()` 会把记录里出现过的分类名视为合法以保护旧 CSV 分类，故**不要据此重置主分类**；判定污染只看「有效分类集合」。
- **地址库台账**：`import_rows()` 必须登记 `book` 到台账（0.9.6），否则界面看得到库、同步却报「目标地址库不存在」。

## 四、关联扫描的金额口径（0.9.8 起，本次对话新增）

**三把尺，各管一段，缺一不可**：

| 字段 | 页面标签 | 作用范围 | 出厂值 |
| --- | --- | --- | --- |
| `min_direct_tao` | 1 级关联最低 TAO | 起始地址直连的**那一笔**转账，按单笔判断、不累计 | `0`（不限金额，旧行为） |
| `min_edge_tao` | 单边最低 TAO | 第 2 跳及更深的单笔转账 | `1` |
| `min_total_tao` | 累计最低 TAO | 每个关联地址所有有效边的金额合计 | `1` |

- 口径唯一由 `LinkPolicy.edge_floor(depth)` 决定（`depth == 0` 用 `min_direct_tao`，其余用 `min_edge_tao`）；`relation.discover()` 与 `crawl.py` 两处都必须调它，**不许再各写一套 `depth == 0` / `current_depth > 0` 的豁免判断**。0.9.7 及以前的三处豁免正是「1 级不限金额、小额蹭关联」的根因。
- 低于对应门槛的转账：既不成为保留边，也不把对手方带进 BFS / Taostats 爬取队列，其下游整条线索随之消失。
- `min_total_tao` 的合计包含该地址作为中转点的下游边，**不能单独用来防蹭关联**（灰尘直连可被自己别处的大额往来撑过门槛）。
- 前端结果表的「金额筛选」只影响显示 / 建库 / 导出，不重新查询、不写进 `policy`；写文档和提示语时必须与三把尺分开说明。
- 三把尺一起落盘到 `data/settings.json` 的 `scan_thresholds`；**空输入框不提交该字段**，后端省略即保持上次保存值（0.9.7 及以前空值被硬塞成 `"1"`，会冲掉用户已保存的设置）。
- 新增 `LinkPolicy` 字段一律**追加到字段末尾**：历史代码有 `LinkPolicy(Decimal("1"), Decimal("0.1"))` 这种位置参数写法，插在中间会静默改掉 `min_total_tao`。
- 门槛只提高蹭关联成本，不是身份判定；彻底排除用「移除关联」（0.9.5 起落库、全机共享）或标为公共地址。

## 五、待用户确认的默认策略（不自行变更）

- `min_direct_tao` 出厂值目前是 **`0`**（保持旧行为，升级后结果不会突然变少）。若用户希望「装好就默认挡住小额蹭关联」，需把出厂值改为 `1` 并同步改 `LinkPolicy` 默认值、`settings_store.DEFAULT_SCAN_THRESHOLDS`、前端输入框 `value`、三份文档及旧测试断言。**未经确认不得改默认。**

## 六、规则冲突处理流程

1. 发现两条规则打架（例如「增量改」与「全盘修复缺陷」边界不清），**先停下手里的实现**，把冲突点、两种做法的后果写清楚反馈给用户。
2. 用户确认后，把结论写进本文件对应章节，并同步到 `.workbuddy/memory/MEMORY.md`。
3. 后续任务以本文件为准；本文件与聊天里的临时口径冲突时，以本文件为准并要求用户确认是否更新。
