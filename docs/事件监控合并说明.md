# 事件监控合并说明（1.0.0）

## 目标与主次

合并后的产品以 **Bittensor 地址关联挖掘** 为主界面，事件监控是左侧栏独立入口。事件模块保留原 Subnet Pulse 的链上、GitHub 和子网档案能力，但不接管主工具布局、地址库编辑和扫描流程。

## 进程与路由

```text
浏览器
  └─ 127.0.0.1:8766 FastAPI 主服务
       ├─ /                        地址扫描、已知地址库、查询记录
       ├─ /event-monitor           事件监控 SPA 与详情页刷新
       ├─ /static/event-monitor/*  合并后的事件前端资源
       └─ /event-api/*             鉴权后的反向代理
             └─ 127.0.0.1:<随机端口>/api/*
                   ├─ ChainCollector
                   ├─ GitHubCollector
                   └─ EventHub SSE
```

事件 HTTP 服务只绑定 `127.0.0.1` 的随机端口。`/event-api/*` 会经过主服务现有的远程访问口令和离线授权中间件，然后流式代理到内部事件服务。事件 SSE、导出文件、JSON 请求和删除请求都走同一条代理链路。

## 数据边界

| 数据 | 数据库 | 说明 |
|---|---|---|
| 已知地址库、分类、地址库台账 | `data/wallet_link.db` | 地址挖掘主数据 |
| 转账索引、扫描记录、自动入库 | `data/wallet_link.db` | 不供事件模块直接写 |
| 事件、原始链上事件、GitHub、子网档案 | `data/event_monitor.db` | 事件高频写入独立库 |
| 事件监控确认名单 `watched_addresses` | `data/event_monitor.db` | 默认空，不自动继承地址库 |

“共用地址库”的实现是事件前端调用主服务 `GET /api/event-monitor/library`，再把用户勾选确认的地址写入事件库 `watched_addresses`。事件模块不直接读取或修改 `address_library`，避免两套业务逻辑各自维护一份地址字段解释。

## 监控确认规则

1. 已知地址库有内容，不代表事件监控已启用任何地址。
2. 事件监控名单默认为空。
3. 事件监控的监控对象是命名地址库，不是散落的单条地址。单地址监控应先在主工具建立只含该地址的地址库。
4. 选择器一级勾选代表整个地址库；展开后可二级勾选，只监控库内部分地址。
5. 搜索优先匹配地址库名；输入地址后 4 位时，反查该地址所属的地址库并展示。
6. 未归入命名地址库的散地址不直接进入事件监控候选；`GET /api/event-monitor/library` 返回 `unbooked_count` 提示数量。
7. 已在事件监控中的地址显示为“已监控”，不能重复勾选。
8. “移出监控”只删除 `event_monitor.db` 中的确认记录，不删除 `wallet_link.db` 的地址资料。
9. 事件监控页按来源地址库分组展示，组标题显示启用数量；来源库记录在 `watched_addresses.library_book`。

## 启动与关闭

主 FastAPI `lifespan` 按以下顺序启动：

1. 初始化地址库 `wallet_link.db`；
2. 初始化事件库 `event_monitor.db`；
3. 启动链上/GitHub 采集线程；
4. 启动内部随机端口 HTTP 服务；
5. 创建事件 API 代理客户端；
6. 启动地址扫描和自动入库后台任务。

关闭时先取消主服务后台任务，再关闭代理客户端、停止事件采集、停止内部 HTTP 服务并释放 SQLAlchemy 连接。

## 依赖决策

项目原有地址扫描使用 `async-substrate-interface`，事件监控原先使用同步 `substrate-interface`。两者分别依赖 `cyscale` 和 `scalecodec`，共用 `scalecodec` 命名空间，不能同时安装。合并后：

- 事件链上采集通过 `app/event_monitor/substrate_adapter.py` 复用 `async-substrate-interface`；
- `requirements.txt` 不包含 `substrate-interface` 或 `scalecodec`；
- 适配器为每个同步采集线程维护独立异步事件循环，并提供 `rpc_request`、`query`、`query_map`、`init_runtime`、`get_events` 和 `close`；
- 关闭适配器时先关闭客户端连接，再取消剩余异步任务和事件循环。

## 旧事件库迁移

旧 `Bittensor_event/data/events.db` 使用以下命令迁移：

```powershell
.\.venv\Scripts\python.exe tools\migrate_event_monitor.py `
  G:\Bittensor_event\data\events.db `
  --target data\event_monitor.db
```

默认行为：

- 使用 SQLite 在线备份 API 复制事件历史；
- 清空旧 `watched_addresses`，符合合并版默认空监控名单；
- 目标库存在时拒绝覆盖，确需覆盖必须加 `--replace`；
- 需要保留旧监控名单时必须显式加 `--keep-watchlist`，不推荐用于正式合并升级。

## 验证重点

- 主页面和事件页面均可打开，事件入口在左侧栏；
- `/event-api/health`、事件 SSE、导出和地址增删改可经主服务代理；
- 已知地址库有地址时，事件监控名单仍为空；
- 勾选确认后只写事件库，移出后主地址库仍存在；
- 桌面和移动端无页面横向溢出、弹窗标题裁切或按钮遮挡；
- `async_substrate_interface` 可导入，旧同步 Substrate 包不进入虚拟环境。
