把下面整段内容发给远端智能体作为第一条指令。内容已自包含，不依赖本机对话历史。

## 一、项目是什么

Bittensor 钱包地址关联挖掘工具：输入一个 SS58 地址，从链上转账记录里按 BFS 挖出与之有关联的地址（默认 3 级，最高 10 级），配一个可维护的地址库，能标记交易所 / 验证者 / 公共地址并在挖掘时自动截断。单机版：FastAPI + SQLite + 原生 JS，跑在本机 `127.0.0.1:8766`，带离线授权（Ed25519 一机一码），支持多设备远程访问与公网隧道。

- 当前版本 **0.8.19**，分支 `main`
- 测试基线 **413 passed**，改完不许低于这个数
- 技术栈：Python 3.12 / FastAPI / SQLAlchemy 2.x / SQLite / 原生 JS（无框架、无打包步骤）
- 21 个后端模块，42 个测试文件

## 二、先跑起来（三条命令）

```bash
# 1. 依赖环境：.venv 不在仓库里，远端必须自己建（离线可用）
cd <项目根> && ./安装.cmd

# 2. 跑测试确认基线（应该是 413 passed）
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY -u all_proxy \
  .venv/Scripts/python.exe -m pytest -q --junitxml=.pytest_full.xml

# 3. 启服务（启动约需 10–13 秒）
.venv/Scripts/python.exe run.py --port 8766
curl -s http://127.0.0.1:8766/api/health    # 应返回 version=0.8.19, licensed=true
```

`installers/` 目录（Python 3.12 安装器 + 全套 wheels，共约 40MB）**是随仓库同步的**，远端装环境不需要联网。`.venv` 本身不进仓库，装完才会出现。

**测试退出码经常不可信**：pytest 退出码 1 常是 safe-delete 钩子拦截临时目录，**以 JUnit 里 `failures=0` 为准**。

## 三、远端一定会踩的坑（先处理再看代码）

### 1. 授权（`license.key` 不在仓库里）

远端首次 `git clone` 后服务能启动，但所有业务接口 403，页面只剩激活页。**这是设计如此，不是 bug。**

- 远端页面会显示自己的 16 位机器码，形如 `KNT5-YFER-N3PA-5W7Z`；也可跑 `.venv/Scripts/python.exe -m app.license` 打印。
- 拿到机器码后，在**持有私钥的那台机器**上签发：
  ```bash
  .venv/Scripts/python.exe tools/issue_license.py --team "内部团队" --machine <远端机器码> --permanent --out license-remote.txt
  ```
  把 `license-remote.txt` 里的 `WL1.xxx` 整串发给远端，页面粘贴激活。
- ⚠️ **别用 `--write`**：它写的是**运行这条命令那台机器**的 `license.key`，不是远端。远端用 `--out` 拿文本、页面粘贴。
- ⚠️ **千万不要在远端跑 `--init-key`**：会生成新密钥对，**所有已发出的授权码全部失效**。
- 私钥固定放在**仓库外**的 `../.license-keys/wallet_link_private.pem`，不进版本库。
- 只改代码跑测试用不着真授权：`tests/conftest.py` 已 `monkeypatch` 掉授权校验，但 **pytest 全绿不代表服务能开**。想看界面就必须激活。

### 2. 数据（`data/` 整目录不在仓库里）

远端起来是一套空库：没有地址库数据、没有查询记录、没有 Taostats key。

- 需要真实数据时，从源机拷 `data/wallet_link.db` 和 `data/settings.json`。
- **拷之前先停服务**：`data/wallet_link.db-journal` 存在说明有未提交事务，热拷会得到不一致快照。
- **`data/settings.json` 里的 Taostats key 是 DPAPI 加密、绑当前 Windows 用户**，换机器/换账号解不开，**必须在新机器页面上重新粘贴 key**。

### 3. 网络出站（0.8.16 的血泪教训，最容易误判）

这台机器（以及国内很多机器）**直连 taostats.io 会超时**，必须走本机代理（Clash 等）。

- `app/taostats.py` 有出站决策层，按序尝试：`WALLET_LINK_HTTP_PROXY` → **Windows 系统代理（WinINET 注册表）** → `HTTPS_PROXY` 等 → 直连；失败会拉黑 600 秒自动换路，并在日志打 `[taostats] 出站请求走 …：原因`。
- **排查第一步永远是看环境自检的「出站网络（taostats.io）」**（页面「更新日志 → 环境自检」，或 `GET /api/diagnose`），它逐条列出每个出站路径的探测结果（HEAD 请求，不带 key、不占额度）。
- **不要把它当成 key 的问题**：0.8.16 之前，网络失败会被误报成"没有可用的 API key"，把排查方向带偏了整整一轮。

### 4. `.probe/` 不在仓库里

这是 UI 数值化核查用的 Chrome CDP 探针脚本目录（已 gitignore）。需要时按第四节的方法新写，别去找。参考实现：`.probe/overflow_probe.js`（node 原生 WebSocket，无第三方依赖）。

## 四、UI 怎么验证（不要靠"看起来没问题"）

改前端后用 Chrome 无头 + CDP 拿真实 DOM 数值。**关键：桌面 Chrome 的 `--window-size` 最小宽度是 500px**，直接传 390 会被钳住、量出来全是假象——手机视口必须用 `Emulation.setDeviceMetricsOverride`：

```js
await send("Emulation.setDeviceMetricsOverride", {
  width: 390, height: 844, deviceScaleFactor: 2, mobile: true,
});
```

Chrome 参数必须是这一组，少一个都会出问题：

```
--headless=new --disable-gpu --no-sandbox --hide-scrollbars
--remote-debugging-port=<唯一端口> --user-data-dir=<绝对路径，且每次换任务换一个>
```

三个反复踩过的坑：

- **量尺寸前必须先把目标视图取消隐藏**。地址库页 `#view-library` 默认带 `hidden`，直接 `getBoundingClientRect()` 全是 `0×0`，看起来像布局崩了。
- **探针里不要手搓半个数据对象**。`renderResult` 要读 `warnings` / `limitations` / `depth_distribution` 等一批字段，拼不全直接抛 `TypeError: data.warnings is not iterable`。正确做法是调页面自己的入口（如 `viewHistoryRecord(id)`）走完整流程。
- **`--user-data-dir` 必须绝对路径**，且每次换端口/换任务换一个，否则前一次的残留进程会占住目录导致拿不到 `type=page`。

## 六、改动的硬性规矩（不做会被测试或页面上打脸）

1. **改静态资源必须同步升版本号**：`VERSION` 文件 + `index.html` 里 `styles.css?v=` 和 `app.js?v=` **两处**。只改一个会导致浏览器拿旧缓存，功能看起来没生效。
2. **CHANGELOG 格式是正则卡死的**：`## <版本> · <标题> · <YYYY-MM-DD>`。标题里**不许出现第二个 `·`**，否则 `ENTRY_PATTERN` 解析失败，`entries[0]` 会落到上一版，`test_version` 直接红。用「、」分隔。
3. **每个修复配一条回归测试**。项目风格是"缺陷 → 测试锁住 → 下次别再犯"，光改代码不加测试不算完成。
4. **数据位数的文案是明写的**。地址显示位数、列宽像素、跳数上限在 `README.md` / `使用说明.md` / `docs/VERIFICATION.md` 里都有具体数字，改代码必须同步改文档。
5. **`使用说明.html` 是产物不是手改文件**：改完 `使用说明.md` 跑 `tools/build_usage_html.py` 重建。
6. **地址截断全站只有一处**：`shortAddr()`（头 4 + 尾 4）。`pathAddr()` 只是薄封装，内部不许再写 `slice(`。
7. **限速和缓存不要为了"跑得更快"去放宽**。免费档就是每分钟 5 次，放宽只会 429。
8. **库归属规则别改回去**：五种人工结论（确认/否定交易所、标记/取消公共地址、重置）**都移出用户地址库**，判据是 `label == book` 且在清 `book` **之前**判断。详见 HANDOFF 第 59 条。
9. **文档结构**：会被读者"按目录找"的内容必须是 `##` 级（离线 HTML 目录只收二级标题）。
10. **提交后 `git push origin main`**，工作区保持干净。

## 七、不要碰 / 不要自作主张

- **不要动授权逻辑**（`app/license.py`、`tools/issue_license.py`）：改错会让所有已发出的授权码失效。
- **不要放宽终点规则**：交易所 / 验证者 / 公共地址 / 系统地址，查到即截止。改松了结果会被噪音灌满。
- **不要为了"结果更多"降低默认门槛**（默认单边 1 TAO、累计 1 TAO）。
- **不要引入前端框架或构建步骤**。分发形态是"拷贝目录 + 双击启动"。
- **不要让两台机器同时跑服务**：限速器是**进程级**的，同一把 key 双跑 = 合计 10 次/分钟 → 429，巡检还会把同一批地址查两遍。
- **不要用 `--tunnel` 之外的组合去采信代理头**：`WALLET_LINK_TRUST_PROXY` 只在隧道模式下打开，否则局域网设备伪造 `CF-Connecting-IP` 就能冒充本机。

## 八、已知遗留（可以挑来做，也可以先问用户）

1. **扫描阈值只记最后一组**。用户在 3 级想用 1/1、10 级想用 10/50，每次切层级要手改。要做需先定"按层级分档"还是"每级各一套"，这是产品决策。
2. **日均频次按自然天数算**，不是实际活跃天数。改成活跃天数需要逐日交易聚合，免费档没有现成接口。
3. **一批老查询记录缺路径**（无 `path_transfers`、边表不连通），只能靠重查补全。
4. **隧道网址每次重启都变**。要固定需"命名隧道 + 自有域名"（年费几十元），客户端仍是零安装。
5. **DPAPI 的跨账号限制**。若服务用 SYSTEM 账号跑计划任务，key 解不开。可选：指定用户账号跑 / 每次重填 / 改 plain 存储（不推荐）。
6. **只读客户端模式**未做。备机打开页面时仍能看到巡检开关和 key 设置，容易误操作。
