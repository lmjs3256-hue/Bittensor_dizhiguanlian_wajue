## 一、项目是什么

Bittensor 钱包地址关联挖掘工具：输入一个 SS58 地址，从链上转账记录里按 BFS 挖出与之有关联的地址（默认 3 级，最高 10 级），配一个可维护的地址库，能标记交易所 / 验证者 / 公共地址并在挖掘时自动截断。单机版：FastAPI + SQLite + 原生 JS，跑在本机 `127.0.0.1:8766`，带离线授权（Ed25519 一机一码）。

- 当前版本 **0.8.5**，分支 `main`，工作区干净，commit `068f8e8`
- 测试基线 **311 passed**，改完不许低于这个数
- 技术栈：Python 3.12 / FastAPI / SQLAlchemy 2.x / SQLite / 原生 JS（无框架、无打包步骤）

## 二、先跑起来（三条命令）

```bash
# 1. 依赖环境：.venv 不在仓库里，远端必须自己建

# 2. 跑测试确认基线（应该是 311 passed）
.venv/Scripts/python.exe -m pytest -q --basetemp=.pytest_tmp/base -p no:cacheprovider

# 3. 启服务（后台跑，启动约需 10–13 秒）

curl -s http://127.0.0.1:8766/api/health   # 应返回 version=0.8.5, licensed=true
```

`installers/` 目录（Python 3.12.10 安装器 + 全套 wheels，共 40MB、35 个文件）**是随仓库同步的**，所以远端装环境不需要联网。`.venv` 本身不进仓库，装完才会出现。

**启动必须等够 12 秒再验证**，跑得比这快说明进程已经挂了（常见于端口占用或依赖没装全）。

## 三、远端一定会踩的三个坑（先处理再看代码）

1. **`license.key` 不在仓库里**（`.gitignore` 里有）。远端首次 `git clone` 后服务能启动，但所有业务接口 403，页面只剩激活页。这是设计如此，不是 bug。
   - 远端机器打开页面会直接显示自己的 16 位机器码，形如 `KNT5-YFER-N3PA-5W7Z`（也可跑 `.venv/Scripts/python.exe -m app.license` 打印）。
   - 拿到机器码后，在**持有私钥的那台机器**上签发并把授权码文本发过去：
     ```bash
     .venv/Scripts/python.exe tools/issue_license.py --team "内部团队" --machine <远端机器码> --permanent --out license-remote.txt
     ```
     然后把 `license-remote.txt` 里的 `WL1.xxx` 整串发给远端，在远端页面粘贴激活。
   - ⚠️ **别用 `--write`**：它写的是**运行这条命令那台机器**的 `license.key`，不是远端。远端用 `--out` 拿文本、页面粘贴。
   - 私钥固定放在**仓库外**的 `../.license-keys/wallet_link_private.pem`，不进版本库。私钥不在远端是正常的，**千万不要在远端跑 `--init-key`**（会生成新密钥对，所有已发出的授权码全部失效）。
   - 如果远端只是改代码、跑测试，用不着真授权：`tests/conftest.py` 已经 `monkeypatch` 掉授权校验，`pytest` 全绿**不代表**服务能开。想看界面就必须激活。
2. **`data/` 整目录不在仓库里**（数据库、本地设置、日志都在里面）。远端起来是一套空库，没有地址库数据、没有查询记录、没有 Taostats key。
   - 需要真实数据验证时，从本机拷 `data/wallet_link.db` 和 `data/settings.json` 过去。
   - `data/settings.json` 里的 Taostats key 是 **DPAPI 加密**、绑当前 Windows 用户，拷到另一台机器解不开，**必须在新机器页面上重新粘贴 key**。
3. **`.probe/` 不在仓库里**。这是本机做 UI 数值化核查用的 Chrome CDP 探针脚本目录（82 个 .py），远端拉不到。需要时按第四节的方法新写，别去找。

## 四、UI 怎么验证（本机没视觉，必须数值化）

改前端后**不要靠"看起来没问题"**，用 Chrome 无头 + CDP 拿真实 DOM 数值：

```python
# 固定套路，本地另存为 .probe/chk_xxx.py（该目录已 gitignore）
# Chrome 参数必须是这一组，少一个都会出问题：
#   --headless=new --disable-extensions --no-first-run
#   --user-data-dir=<绝对路径，且每次换端口/换任务换一个>  --remote-debugging-port=<唯一端口>
#   --window-size=1440,1100  http://127.0.0.1:8766/?t=<随机>
```

两个反复踩过的坑：
- **量尺寸前必须先把目标视图取消隐藏**。地址库页 `#view-library` 默认带 `hidden`，直接 `getBoundingClientRect()` 全是 `0×0`，看起来像布局崩了。
- 探针里想复用页面函数（如 `renderResult`）时，**不要手搓半个数据对象**。`renderResult` 要读 `warnings` / `limitations` / `depth_distribution` 等一批字段，拼不全直接抛 `TypeError: data.warnings is not iterable`。正确做法是调页面自己的入口（例如 `viewHistoryRecord(id)`）走完整流程。

## 六、改动的硬性规矩（不做会被测试或页面上打脸）

1. **改静态资源必须同步升版本号**：`VERSION` 文件 + `app/templates/index.html` 里 `styles.css?v=` 和 `app.js?v=` 两处。只改一个会导致浏览器拿旧缓存，功能看起来没生效。
2. **CHANGELOG 格式是正则卡死的**：`## <版本> · <标题> · <YYYY-MM-DD>`。标题里**不许再出现第二个 `·`**，否则 `app/version_info.py` 的 `ENTRY_PATTERN` 解析失败，`tests/test_version.py` 直接红。
3. **每个修复配一条回归测试**。项目风格是"缺陷 → 测试锁住 → 下次别再犯"，光改代码不加测试不算完成。
4. **数据位数的文案是明写的**。地址显示位数、列宽像素、跳数上限这些在 `README.md` / `使用说明.md` / `docs/VERIFICATION.md` 里都有具体数字，改代码必须同步改文档，否则文档自相矛盾。
5. **`使用说明.html` 是产物不是手改文件**：改完 `使用说明.md` 跑 `tools/build_usage_html.py` 重建。
6. **地址截断全站只有一处**：`shortAddr()`（头 4 + 尾 4）。`pathAddr()` 只是它的薄封装，内部不许再写 `slice(`。
7. **限速和缓存不要为了"跑得更快"去放宽**。Taostats 免费档就是每分钟 5 次，放宽只会 429。层级越深需要的请求越多，正确做法是让用户多点几次靠缓存递进。
8. **提交后 `git push origin main`**，工作区保持干净。

## 七、不要碰 / 不要自作主张

- **不要动授权逻辑**（`app/license.py`、`tools/issue_license.py`）：这是商业分发的地基，改错会让所有已发出的授权码失效。
- **不要放宽终点规则**：交易所 / 验证者 / 公共地址 / 「系统」分类的地址，查到即截止不再展开。这是结果干净的核心，改松了结果会被噪音灌满。
- **不要为了"结果更多"降低默认门槛**（默认单边 1 TAO、累计 1 TAO）。用户要更多结果会自己抬层级、抬门槛，那是有意的。
- **不要引入前端框架或构建步骤**。这个项目的分发形态是"拷贝目录 + 双击启动"，加 node_modules 会让它跑不起来。

## 八、已知遗留（可以挑来做，也可以先问用户）

1. **扫描阈值只记最后一组**：现在 `data/settings.json` 只存一组 `min_edge_tao` / `min_total_tao`。用户在 3 级时想用 1/1、10 级时想用 10/50，每次切层级都要手改。要做的话得先定"按层级分档"还是"记住每个层级各一套"，这是产品决策，别自己拍。
2. **日均频次按自然天数算**，不是实际活跃天数。改成活跃天数需要逐日交易聚合，Taostats 免费档没有现成接口。
3. **一批老查询记录缺路径**（无 `path_transfers`、边表也不连通），只能靠重查补全。`docs/HANDOFF.md` 里有 `unverified=180` 的历史背景。
4. **Taostats 长时间不可达时**，3 次重试（约 3.6 秒）后返回 502。界面已显示原始错误文本，可以按需加更友好的降级提示。
