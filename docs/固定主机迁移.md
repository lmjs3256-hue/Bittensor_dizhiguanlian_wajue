# 固定主机迁移交接文档

> **适用场景**：现在这台电脑只是**测试机**。将来要把服务搬到一台**远端固定主机**上，长期常开、对外提供访问。
>
> **读者**：接手迁移的人（或未来的自己）。不需要读过之前的对话，本文自包含。
>
> **当前状态**：测试机 `PC-20260506JBNA`（Win11），版本 0.8.19，Tailscale 地址 `100.95.206.119`，机器码 `GVGH-QRJP-5QC4-ZQLX`。

## 一、先明确三件事，否则会白折腾

### 1. 迁移的不是"文件夹"，而是三样东西

| 要搬的 | 在哪 | 能不能直接拷 | 说明 |
| --- | --- | --- | --- |
| **代码** | 仓库 / 整个文件夹 | ✅ 能 | 用 `git clone` 最干净 |
| **数据** | `data/` 目录 | ✅ 能（注意时机） | 数据库 + 配置，**这是唯一有价值的资产** |
| **授权** | `license.key` | ❌ **不能** | 一机一码，换机必须重新签发 |
| **Taostats key** | `data/settings.json` 里 | ❌ **不能** | Windows DPAPI 加密，绑用户绑机器，换机解不开 |

**只有后两项需要人工介入**，也是最容易在迁移当天卡住的地方。先把这两件办了，其余都是复制粘贴。

### 2. 远端主机的三条硬性要求

1. **Windows 系统**（一键脚本、DPAPI、`start.ps1` 全是 Windows 专用）。Linux 能跑但要手动建环境，且 DPAPI 相关逻辑要改。
2. **能长时间不休眠**。电源设置里把"睡眠"设为"从不"，屏幕可以关。服务靠进程常驻，机器睡了就全断。
3. **网络出口能到 taostats.io**。这是 0.8.16 踩过的坑：国内直连 taostats.io 会超时，需要系统代理或 `WALLET_LINK_HTTP_PROXY`。**迁移前先在远端测一次**，别等搬完了才发现查不了数据。

### 3. 必须停掉测试机上的服务

**同一把 Taostats API key，同一时刻只能有一台机器在工作。** 原因不是"约定"，是硬限制：

- 限速器 `_reserve_request()` 是**进程级**滑动窗口。两台各跑一份，各自认为 5 次/分钟没问题，服务端看到的是同一把 key 合计 10 次/分钟 → 直接 429；
- 巡检每个地址 2 次请求，两台各跑一遍 = 同一批地址查两遍，额度翻倍、产出为零。

所以迁移完成后，**测试机要么彻底停掉服务，要么只当浏览器客户端访问远端**（推荐后者）。

## 二、迁移前的准备（在测试机上做）

### 2.1 拿到远端主机的机器码

在远端主机上装好代码（见第三节），启动一次服务，页面会停在激活页并显示 16 位机器码。也可以在远端执行：

```powershell
.\.venv\Scripts\python.exe -m app.license
```

输出形如 `ABCD-EFGH-JKLM-NPQR`。**记下这个码**。

> ⚠️ 机器码的算法：Windows 读注册表 `SOFTWARE\Microsoft\Cryptography\MachineGuid`。**重装系统会变**，届时需要重新签发。换机器、换系统必然变，`license.key` 拷过去不认。

### 2.2 在持有私钥的机器上签发授权码

私钥固定放在**仓库之外**的 `../.license-keys/wallet_link_private.pem`，**不在版本库里**。

```powershell
# 在持有私钥的那台机器上执行（不是在远端！）
.\.venv\Scripts\python.exe tools\issue_license.py --team "内部团队" --machine <远端机器码> --permanent --out license-remote.txt
```

把 `license-remote.txt` 里的 `WL1.xxx` 整串文本保存好，稍后在远端页面粘贴激活。

> ⚠️ **别用 `--write`**：它写的是**运行这条命令那台机器**的 `license.key`，不是远端。远端必须用 `--out` 拿文本、再到页面上粘贴。
>
> ⚠️ **千万不要在远端跑 `--init-key`**：那会生成新的密钥对，**所有已发出的授权码全部失效**，包括你自己在用的。

### 2.3 导出数据

**停掉测试机服务，再拷数据**（`data/wallet_link.db-journal` 存在说明有未提交的事务，直接拷可能拷到不一致的快照）：

```powershell
# 测试机上
.\停止.cmd

# 拷走这三个（数据库 + 配置 + 授权，授权其实不用带）
# data\wallet_link.db
# data\settings.json
```

`data/` 里其它文件不用带：

- `wallet_link.db.bak_*` — 历史备份，确认新环境跑通后再说；
- `.license-clock` — 授权时钟，新机器会用新授权重新生成；
- `logs/` — 日志，不必搬。

### 2.3.1 本地索引（`transfers` 表）怎么迁——**这是最容易漏的一块**

本地索引就存在 `data\wallet_link.db` 的 `transfers` 表里，**不是单独的文件**。所以
**拷走 `wallet_link.db` 就等于把本地索引一起搬走了**，不需要额外操作。

但有三件事必须知道，否则迁移后会以为"索引坏了"：

**① 索引可以丢，代价是重新攒**

| 表 | 内容 | 丢了会怎样 |
| --- | --- | --- |
| `address_library` | 地址库（2500+ 条地址、分类、备注、库归属） | **不能丢**，这是核心资产 |
| `watch_state` | 巡检游标、已查进度 | 丢了大不了重查一遍 |
| `transfers` | 本地索引（链上转账明细） | 丢了要重新扫链攒回来，功能不受影响 |
| `auto_import_log` / `relation_archives` | 入库日志 / 历史查询快照 | 丢了只是查不到历史 |

如果只想搬"资产"不想搬"索引"（数据库从 67MB 降到几 MB），可以**只导地址库**，到新机器上重新扫链。但没有必要——整个库一起拷最简单。

**② 迁移后索引一定落后，这是正常的**

本地索引是按块向前扫的，停机那段时间的块没人扫。迁移完第一次启动时：

- 索引游标停在旧位置，链头已经往前走了很远；
- **不需要手工干预**：0.8.36 起后台自动扫描每轮扫 75 块（约 50 块/轮回补欠账），会自己追上；
- 落后多少可以看：`GET /api/overview` 返回的 `index.lag_blocks` / `index.lag_minutes`（`0` 表示已追平），页面「更新日志 → 环境自检」也会显示。

想立刻追平（不等后台慢慢补），手工触发几次扫描即可：

```powershell
# 先看落后多少（index.lag_blocks / index.lag_minutes）
curl -s http://127.0.0.1:8766/api/overview

# 每次推进 16 块（手动接口上限），连点几十次；或等后台每 5 分钟自动跑
curl -X POST "http://127.0.0.1:8766/api/scan?blocks=16&advance=true"
```

**③ 索引不连续时，巡检会自动退回 API（不省额度）**

0.8.36 起巡检默认「本地索引优先」，但判据很严：**本地必须连续覆盖**那段区间才敢不发 API。迁移后索引一定是断的（停机那段缺失），所以**初期巡检仍会全部走 Taostats**，等索引补齐并连续之后才逐步省下来。这是设计如此，不是没生效。

> 一句话总结：**迁 `wallet_link.db` 一个文件就够，索引跟着走；落了也没事，会自动重扫；断档期间巡检退回 API，不影响正确性。**

### 2.4 记录当前的关键配置（迁移后要核对）

| 配置 | 当前值 | 存在哪 |
| --- | --- | --- |
| 扫描阈值 | 单边 1 / 累计 1 TAO | `settings.json` → `scan_thresholds` |
| 巡检开关 | **关闭**（`enabled=false`） | `settings.json` → `address_watch` |
| 巡检日预算 | 700 次 | 同上 |
| 访问口令 | 迁移后会变（除非手工保留） | `settings.json` → `access_token` |

## 三、在远端主机上部署

### 3.1 装代码

```powershell
# 方式一：从仓库拉（推荐，最干净）
git clone <仓库地址> bittensor-wallet-link-intel
cd bittensor-wallet-link-intel

# 方式二：整个文件夹拷过去（记得不要带 .venv，它换机器后会失效）
```

### 3.2 建运行环境（离线可用）

```powershell
.\安装.cmd
```

`installers/` 目录里带了 Python 3.12 安装器 + 全套 wheels（约 40MB），**不需要联网**。装完会生成 `.venv/`。

重复双击是安全的：已装好的部分自动跳过。

### 3.3 放数据

把 2.3 拷出来的 `wallet_link.db` 和 `settings.json` 放进远端项目的 `data/` 目录（目录不存在就新建）。

> ⚠️ **`settings.json` 里的 Taostats key 在新机器上是解不开的**（DPAPI 绑用户+机器）。文件本身可以放，但迁移后必须**在远端页面上重新粘贴一次 key**。这一步躲不掉，详见 3.5。

### 3.4 激活授权

```powershell
.\启动.cmd
```

页面会停在激活页，粘贴 2.2 拿到的 `WL1.xxx` → 激活。成功后会生成 `license.key`。

验证：

```powershell
.\.venv\Scripts\python.exe run.py --doctor
```

`代码版本 / 预置验证者文件 / 落库情况 / API key` 四项逐条列出，退出码 1 表示有项目没通过。

### 3.5 重新配置 Taostats key（必做）

打开页面 → 「Taostats API key」→ 粘贴 → 保存。

保存后 `settings.json` 里的 `taostats_api_key` 会被**新机器的 DPAPI 重新加密**，之后重启就不用再填。

**然后立刻验证出站网络**，这是 0.8.16 的核心教训：key 配了不代表查得通。

- 页面上点「更新日志 → 环境自检」，看 **「出站网络（taostats.io）」** 这一项：
  - `pass 当前走系统代理（http://127.0.0.1:7890）可达` → 正常；
  - `fail 所有出站路径都不通` → 远端网络到不了 taostats.io，需要配代理。
- 如果远端有 Clash / v2rayN 之类的代理，**只要系统代理开着就会被自动识别**（本项目读 WinINET 注册表）。
- 如果代理不在系统设置里，用环境变量显式指定：

  ```powershell
  # 在启动脚本前设置，或在系统环境变量里永久添加
  $env:WALLET_LINK_HTTP_PROXY = "http://127.0.0.1:7890"
  ```

  填 `none` 则强制直连。

### 3.6 数据核对

逐项确认，别只看"页面能打开"：

- [ ] 地址库条数与测试机一致（按「角色筛选」分别核对公共地址 / 交易所 / 验证者数量）
- [ ] 查询记录（历史）能打开，能展开「路径明细」
- [ ] 起始地址输入框能记住上次查询（0.8.17 起，存在浏览器本地，换浏览器会丢，属正常）
- [ ] 巡检开关状态与测试机一致（当前应为**关闭**）
- [ ] 扫描阈值是 1 / 1

## 四、决定远端怎么对外提供服务

远端主机的价值是"常开、随时可访问"。两种方式，**建议优先 Tailscale**。

### 4.1 方案对比

| 方案 | 地址 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| **Tailscale（推荐）** | `http://100.x.x.x:8766` | 地址**固定不变**；私有网段，公网路由不到，扫不着的 | 每台客户端要装 Tailscale App 并保持开启 | 自己/团队内部日常使用 |
| **Cloudflare 隧道** | `https://xxx.trycloudflare.com` | 客户端**零安装**，任意浏览器 | 网址**每次重启就换**；挂在公网上 | 临时借别人设备看一眼 |

**为什么优先 Tailscale**：`100.x` 是私有网段，互联网上根本路由不到，"门不存在"和"有个门但要密码"不是一个安全等级。而且地址固定，可以直接存书签。

### 4.2 Tailscale 方案（推荐）

远端装 Tailscale 并登录同一个账号，然后：

```powershell
.\启动-远程访问.cmd
```

启动面板会打印：

```
 访问口令   XXXX-XXXX-XXXX-XXXX
 本机       http://127.0.0.1:8766
 Tailscale  http://100.x.x.x:8766
 局域网     http://192.168.x.x:8766
```

客户端打开 `http://100.x.x.x:8766`，输一次口令，记住 90 天。

**在远端主机上要额外做的两件事**：

1. **Tailscale 设为开机自启**（安装时默认勾选，确认一下）。
2. **让 Tailscale 在无人登录时也能工作**：Tailscale 是系统服务，锁屏状态下仍可访问，不需要"用户已登录桌面"。但**服务本身要有人启动**——见第五节。

### 4.3 隧道方案（临时用）

```powershell
.\启动-公网隧道.cmd
```

面板会直接印出 `公网入口 https://xxx.trycloudflare.com`（0.8.19 起，从 `logs/cloudflared.url` 读取）。

**必须知道的**：

- 隧道进程跟着命令行窗口活着，**窗口关掉、机器重启就断**；
- 每次启动**换新网址**，旧网址作废；
- 想固定网址 → 需要自己的域名托管到 Cloudflare，配"命名隧道"（本文不展开，需要时单独做）。

### 4.4 防火墙

`--remote` 会监听 `0.0.0.0:8766`，但 Windows 防火墙可能拦。首次启动时若有弹窗，勾选「专用网络」。

若没有弹窗却连不上，手工加一条入站规则（管理员 PowerShell）：

```powershell
New-NetFirewallRule -DisplayName "Bittensor 地址挖掘 8766" -Direction Inbound `
  -LocalPort 8766 -Protocol TCP -Action Allow -Profile Private,Domain
```

> 只放 `Private,Domain`，**不要放 `Public`**。用 Tailscale 时流量走 Tailscale 虚拟网卡（Private），够用了。

## 五、让服务开机自启（远端主机的关键一步）

远端机器会重启（断电、系统更新），**服务不会自己起来**——它是靠双击脚本启动的前台进程。需要配置成自启。

### 5.1 方式一：启动文件夹（最简单）

1. `Win + R` → 输入 `shell:startup` → 回车；
2. 把 **`启动-远程访问.cmd`** 的快捷方式拖进弹出的文件夹。

**限制**：只有**用户登录后**才会执行。如果是无人值守的服务器，重启后没人登录，就起不来。

### 5.2 方式二：计划任务（推荐给真正的服务器）

用管理员 PowerShell 创建，**不依赖用户登录**：

```powershell
$root = "C:\bittensor-wallet-link-intel"     # 换成实际路径
$action  = New-ScheduledTaskAction -Execute "$root\.venv\Scripts\pythonw.exe" `
           -Argument "run.py --remote --port 8766" -WorkingDirectory $root
$trigger = New-ScheduledTaskTrigger -AtStartup
$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries `
           -DontStopIfGoingOnBatteries -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1)
$principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -LogonType ServiceAccount -RunLevel Highest

Register-ScheduledTask -TaskName "BittensorWalletLink" -Action $action `
  -Trigger $trigger -Settings $settings -Principal $principal
```

**注意事项**：

- 用 `pythonw.exe` 而不是 `python.exe`，避免弹出黑窗口。
- 用 `SYSTEM` 账号时，**DPAPI 加密的 key 解不开**（DPAPI 绑用户）。所以要么改成"用你自己的账号、勾选『不管用户是否登录都运行』并存储密码"，要么接受"每次重启后到页面上重填一次 key"，要么改用 `plain` 存储（安全性下降，不推荐）。
- 启动后服务日志在 `logs/wallet-link.stderr.log`，`pythonw` 不显示窗口，**出问题只能看日志**。

> **如果远端是"一台常开的 Windows 桌面电脑"而不是服务器**，用 5.1 更省事，且不受 SYSTEM 账号的 DPAPI 限制。这种情况建议：5.1 + 电源设置里关闭睡眠 + 关闭"需要登录才能使用"（或用自动登录）。

### 5.3 验证自启是否生效

重启远端 → 不打开任何页面 → 在**另一台设备**上访问 `http://100.x.x.x:8766/api/health`，能返回版本号就说明服务自己起来了。

## 六、停掉测试机（别漏了这步）

迁移完成后，**测试机必须停止服务和一切定时任务**，否则两把限速器同时工作 → 429、额度翻倍。

```powershell
# 测试机上
.\停止.cmd
```

如果测试机也想继续用，正确做法是：**只开浏览器访问远端的地址**，本地不再启动服务、不再配 key（key 可以留着无所谓，只要服务不跑）。

确认测试机没有残留：

```powershell
# 应该没有任何输出
Get-NetTCPConnection -LocalPort 8766 -State Listen
Get-Process cloudflared -ErrorAction SilentlyContinue
```

## 八、回滚

万一远端跑不起来，**测试机是可靠的回退点**：

1. 远端 `.\停止.cmd`；
2. 测试机 `.\启动.cmd`（原授权、原数据都在，未受影响）；
3. 确认测试机 `http://127.0.0.1:8766/api/health` 正常。

**前提**：迁移过程中不要删除测试机的 `data/` 和 `license.key`。建议迁移期间，把测试机的 `data/` 额外复制一份到别处。

> 如果远端已经产生新数据（查了新地址），回滚后需要把远端的 `wallet_link.db` 拷回测试机覆盖。两份数据不要长期并存——`data/` 是单文件 SQLite，没有合并机制（导出 JSON 同步包是给"离线对账"用的，不是日常协同手段）。

## 九、常见问题

**Q：远端页面一直停在激活页？**
`license.key` 没生成或机器码对不上。重跑 `python -m app.license` 看当前机器码，和签发的那个比对。注意：**重装系统、换主板、改计算机名一般不影响**（读的是 `MachineGuid`），但**重装 Windows 会变**。

**Q：远端能打开页面，但查询报"连不上 Taostats"？**
远端网络到不了 taostats.io。这是 0.8.16 修复的那类问题：先看环境自检的「出站网络」，再决定配系统代理还是设 `WALLET_LINK_HTTP_PROXY`。**不要以为是 key 的问题**——0.8.16 之前就是这种误报把人带偏了。

**Q：远端 key 填了、重启后又变回"未配置"？**
DPAPI 绑当前用户。检查两点：① 服务是不是用**另一个账号**跑的（计划任务用 SYSTEM 就会这样）；② `data/settings.json` 的 `taostats_api_key` 里 `enc` 是不是 `dpapi`。跨账号/跨机器都解不开，只能重填或改用计划任务指定你自己的账号。

**Q：两台机器都开过服务，现在查询总被限流？**
确认另一台真的停了。`Get-NetTCPConnection -LocalPort 8766 -State Listen` 在两台上都查一遍。同一把 key 同时只有一个进程在用。

**Q：远端重启后服务没自动起来？**
按第五节配了自启吗？用 `shell:startup` 的话，**必须有人登录桌面**才会执行；无人值守要用计划任务。

**Q：手机在外面打不开 `100.x.x.x`？**
手机上的 Tailscale 要**保持开启**。iOS 长时间不用会休眠，回 App 点一下即可（不用重新登录）。忘了开的现象就是页面一直转、最后超时——不是工具坏了。可以在主机上 `tailscale status` 确认那台设备是否 `online`。

**Q：能不能直接用公网 IP 访问？**
云服务器可以（要开安全组），但**强烈不建议**：没有 HTTPS，口令是明文传输的，Cookie 有效期 90 天，一旦被抓到等于 90 天都能进你的地址库、花你的 API 额度。用 Tailscale（私有网段）或隧道（自带 HTTPS）。
