Bittensor 地址关联挖掘 · 使用说明

这份说明写给第一次使用的人，不需要懂编程。照着做，大约 5 分钟能让工具跑起来。 只想快速开始？直接跳到 三、安装 和 五、第一次查询。 想让手机、外网也能打开这个页面？见 十一、多设备访问（含公网隧道、重启后地址会不会变）。 开发与设计细节见 README.md，版本变化见 CHANGELOG.md。

一、这个工具能做什么

输入一个 Bittensor 钱包地址，查出和它发生过资金往来的其他钱包，并标注这些钱包是不是已知的交易所、验证者或黑名单地址。

具体能回答这些问题：

你想知道 工具给出的结果
这个地址和哪些钱包有资金往来 关联地址清单，含层级、流入/流出/累计金额
钱是不是经过中转 1 级 = 直接转账，2 级及以上 = 中间隔了几层中转（最高 10 级）
对方是不是交易所 命中地址库时显示“交易所地址”“疑似交易所（待确认）”等标签
能不能拿去别处用 一键导出 TXT（每行一个地址）或 JSON
上次查的结果还在吗 每次查询自动保存进“查询记录”，可回看、重导

它不能做什么（这点很重要，避免误用）：

  • 不能证明两个地址属于同一个人。工具表达的是“发生过资金关联”，不是身份结论。
  • 不能保证查到全部历史。公开节点和免费 API 都有覆盖范围限制，结果里会写明数据来源和截止区块。
  • 不会动你的钱包。全程只读公开数据，不签名、不转账、不需要助记词或私钥。

安全提示：任何情况下都不要把助记词、私钥、keystore 文件输入给这个工具或任何网站。这个工具只需要一个公开的收款地址。

三、安装（只需一次）

情况 A：从 GitHub 下载

  1. 打开项目主页：https://github.com/lmjs3256-hue/Bittensor_dizhiguanlian_wajue
  2. 点绿色 Code 按钮 → Download ZIP
  3. 解压到一个固定位置，例如 D:\Bittensor_dizhiwajue - 路径建议全英文、不带空格和 #、& 等符号，可减少奇怪的报错 - 不要放在 C 盘的 Program Files 里（需要管理员权限）
  4. 进入文件夹，双击 安装.cmd
  5. 等窗口跑完，看到 “安装完成” 就好了。首次安装约 2–5 分钟。

整个过程不需要联网：电脑上没有 Python 时，脚本会直接用文件夹里 installers\python-3.12.10-amd64.exe 静默安装；依赖也从 installers\wheels\ 本地安装。

情况 B：别人直接拷给你的文件夹

同样是双击 安装.cmd。

如果这个文件夹在别的电脑上装过，里面的 .venv 运行环境会失效（它记录的是原电脑的路径），安装脚本会自动检测并重建，不用你手动删。

安装脚本到底做了什么

步骤 动作 失败时的表现
1 找可用的 Python（3.10–3.13，包括装了但没加进 PATH 的情况）；已有就跳过 找不到就用 installers\ 里的安装包静默安装，再不行才联网用 winget
2 创建独立运行环境 .venv；已有可用的就跳过 自动重建失效的环境
3 优先从 installers\wheels\ 离线安装依赖，版本不匹配才联网（官方源失败自动切国内镜像）；依赖已完整且清单没变就跳过 提示检查网络后重新双击
4 建 data、logs 目录，创建桌面快捷方式；已存在就跳过 快捷方式失败不影响使用，改用 启动.cmd

安装过程不会修改系统 Python、不写注册表、不需要管理员权限（除 winget 装 Python 可能弹一次确认）。

重复双击安装会重装吗？

不会。 脚本每一步都先检查，已经具备的直接跳过，所以重复运行是安全的，通常 1–2 秒就结束：

检查项 已就绪时看到什么
Python [--] Python 3.12.x 已就绪，不动它
.venv [--] 已有可用的 .venv，跳过创建
依赖 [--] 依赖已完整（pip check 通过），跳过安装，不会升级 pip、不会联网
快捷方式 [--] 桌面快捷方式已指向本项目，跳过创建

结尾会明确写一行 “环境已就绪：本次没有重复安装任何组件。”

需要它重新装的情况：

  • 你改了 requirements.txt → 脚本发现指纹变了，只重装依赖；
  • 环境被误删或被杀毒软件清理 → 自检不通过，自动补装；
  • 想彻底重来 → 先双击 停止.cmd，再在本文件夹的 PowerShell 里执行 .\setup.ps1 -Force（删除 .venv 后重装，约 15 秒）。

如果电脑上没有 Python

安装脚本会自动处理，不用你操心：

  1. 先在常见位置找一遍（包括“装好了但没加进 PATH”的情况）；
  2. 找不到就静默运行文件夹里的 installers\python-3.12.10-amd64.exe（装到当前用户目录、自动加 PATH、不需要管理员权限）；

  3. 只有上面两步都失败（例如系统策略禁止安装），才需要手动装：

  4. 双击 installers\python-3.12.10-amd64.exe

  5. 安装界面底部务必勾选 “Add python.exe to PATH”，点 Install Now
  6. 装完回到文件夹，重新双击 安装.cmd

如果你手动装的是 3.13 而非 3.12，installers\wheels\ 里的依赖包会不匹配，此时脚本会自动改为联网安装。

四、启动与关闭

启动

三种方式，任选一种：

  • 双击桌面上的 “Bittensor 地址关联挖掘” 快捷方式（推荐）
  • 双击文件夹里的 启动.cmd
  • 需要换端口时，在本文件夹的 PowerShell 里执行 .\start.ps1 -Port 8777（也可以 启动.cmd 8777）

启动成功后浏览器会自动打开 http://127.0.0.1:8766。如果 8766 已被同一台电脑上的另一份副本占用，脚本会自动改用 8767 之类的空闲端口启动，并在窗口里提示实际端口。

服务在后台运行，关掉浏览器页面不影响；想再打开页面，直接访问上面的地址即可，不用重新启动。

启动窗口里会明确显示结果：已在浏览器打开：http://127.0.0.1:8766。如果显示的是“没能自动打开浏览器”，把窗口里给出的地址复制到浏览器打开即可（通常是这台电脑没有设置默认浏览器）。窗口 5 秒后自动关闭，服务继续在后台运行。

第一次启动可能比平时慢（杀毒软件要扫描一遍新文件），窗口会每隔 10 秒提示“还在启动…”，最多等 90 秒；看到 Ready: http://… 就说明好了。

关闭

双击 停止.cmd。电脑重启后服务不会自动启动，需要再次双击快捷方式。

想让手机 / 另一台电脑也能用这套工具，或者人在外面要访问，看 十一、多设备访问。那里的「公网隧道」做法客户端不用装任何软件，但网址每次重启都会换，原因和替代方案都写在那节里。

在同一台电脑上复制一份做测试（换个磁盘或目录）

可以，而且不用重新安装、也不用重新激活：

  1. 把整个文件夹复制到别的磁盘或别的目录（例如 D:\wallet_link_test），data\、license.key、.venv\ 一起拷过去；
  2. 双击副本里的 启动.cmd；
  3. 如果原副本正占着 8766，窗口会提示“端口 8766 已被 … 占用，本副本改用 8767”，然后用新端口启动并自动打开对应页面 —— 不会串到原副本的页面。

为什么不用重新激活：机器码只由 Windows 系统本身派生，跟文件夹在哪个磁盘、叫什么名字无关。同一台电脑上机器码不会变，所以拷过去的 license.key 照样有效。只有换电脑或重装系统才会变，那时才需要找管理员重签。

两个副本的数据是各自独立的两套：副本里查的记录、建的地址库都写在副本自己的 data\wallet_link.db 里，不会同步回原目录。测完把副本文件夹直接删掉即可，不用卸载，也不影响原目录。

判断自己开的是哪一份，看地址栏端口就行（8766 是原来那份，8767 是副本）；两边右下角水印相同是正常的——同一台电脑、同一个授权。

如果页面打不开

  1. 看右下角：启动窗口是否报错？
  2. 手动在浏览器输入 http://127.0.0.1:8766/api/health，正常会返回一段 JSON，里面有 "ok":true 和版本号
  3. 还是不行，看 logs\wallet-link.stderr.log 最后几行，通常会直接写原因

第一次启动需要激活（授权绑定电脑）

工具是授权使用的，防止拷贝外流。首次启动会看到“这台电脑还没有激活”的页面，上面直接显示一个 16 位机器码（形如 KNT5-YFER-N3PA-5W7Z）：

  1. 点“复制”，把机器码发给管理员；
  2. 管理员签发一串 WL1. 开头的授权码发回给你；
  3. 粘贴到输入框，点 激活，页面自动刷新即可使用。

激活信息保存在程序目录下的 license.key 里，全程不联网。激活后页面右下角会常驻“团队名 · 机器码后 6 位”水印，导出的地址 TXT/JSON 也会带上“授权给 …”标记——万一工具或数据外流，可以追溯到是哪个团队的副本。授权码默认一年有效，到期后重新找管理员要一个新码；换电脑或重装系统后机器码会变，同样需要重新申请。

小提示：激活不需要另外装 Python，双击 启动.cmd 用的就是文件夹里的 .venv。tools\ 目录里的 .py 文件双击不会运行（这是正常的，Windows 不认），需要动手时都用配套的双击脚本：管理员签发授权码用 签发授权.cmd，查看本机机器码用 查看机器码.cmd。

管理员怎么签发授权码，见 授权管理.md。

打开页面后，顶部是“起始地址”，右边就是 扫描关联 按钮。

点 扫描关联 开始。

分轮续查是怎么回事

Taostats 免费额度限制每分钟 5 次请求，一次查询装不下所有关联。所以工具会：

  1. 第 1 轮用掉 5 次请求，查最优先的地址（1 级关联和转账明细优先，余额查询排最后）；
  2. 等约 1 分钟，第 2 轮从上次没查完的两个地址继续；
  3. 一直循环到查完、或达到你设的轮数上限。

界面上会实时显示：第 3 轮 / 5 轮、这一轮准备查什么、还剩多少个待查对象。嫌慢或已经够用，随时点 停止续查——当前请求一结束（最长约 20 秒）就出结果，已查到的关联会保留，可以照常查看和导出，并会告诉你还剩多少没查。

结果怎么看

点「扫描关联」后，工具先查起始地址画像、立刻填进左侧栏，然后才继续扫关联地址。所以你会在 2～3 秒内看到四项指标先显示「查询中…」、再变成真实数字，而结果表要等关联跑完才出现——不用再盯着一个转圈的按钮猜进度。

画像显示在左侧栏导航下方的空白处（不占结果阅读宽度）：地址显示为头 4 + 尾 4 位（例如 5Hiv…N8kS），鼠标悬停可看完整地址，后面的「复制」按钮复制的是完整 48 位地址。下面是四个指标：

指标 含义
注册日期 这个地址第一次上链的时间，副行标注注册网络（nakamoto 是最早期网络，finney 是现在的主网）
质押次数 该地址在子网里做过多少次质押操作——质押（stake）和解质押（unstake）各算一次。这是 Taostats 给出的全量数字，和本次查询翻了几页无关；不是普通转账笔数
日均频次 质押操作次数 ÷ 注册至今的天数。注册当天按 1 天算；数字越大说明这个钱包在子网里越活跃
余额 总余额 = 可用 + 质押 + 预留，副行把可用和质押拆开显示

窗口较窄（≤950px，左侧栏变成顶部横条）时，这块会自动搬回结果区顶部，改成横向四列（手机宽度两列），不影响阅读。

想看的数据没出来（显示「未获取」），通常是这三种情况：

  • 没配 Taostats API key：注册日期、交易次数、总余额都来自 Taostats。副行会写「需要 Taostats API key」。
  • 额度用完了：Taostats 有 5 次/分钟的本地保护限速。等一分钟重查一次即可，结果会缓存在内存里 5 分钟。画像本身固定占 2 次请求（注册日期+余额 1 次、质押总量 1 次），这 2 次会从当轮 5 次额度里扣掉，所以一次完整扫描最多是「2 次画像 + 3 次关联」；画像命中 5 分钟缓存时不占额度。
  • 用的是本地索引模式：本地库里只有子网 stake 转移边，没有质押/解质押的操作事件，所以质押次数仍然走 API 取真实值（只要你配了 key）。只有完全没配 key 时才会降级成「本地索引内的转账笔数」并标注「本地索引无质押事件，改为转账笔数」——这时日均频次也不显示，因为两种口径不同，除出来的数字是假的。

这四项永远不会用 0 冒充：真的是 0（比如已被清空的地址）就显示 0，取不到就显示「未获取」，两者区分得开。画像取不到也不影响查询本身，关联结果照常出。

结果表每行是一个关联地址：

列 含义
关联地址 对方钱包地址，可点击复制
层级 1 = 与起始地址直接转账；2 级及以上 = 通过上一级地址中转（最高 10 级）；每一行都可点「路径明细」展开从起始地址到它的逐笔转账（时间、区块、金额）
关联强度 极强 / 强 / 中 / 弱，按累计转账金额分档；鼠标悬停看依据
流入 / 流出 这个地址与起始地址方向的资金规模（TAO）
累计 往来总额，可用于排序判断亲密度
标签 地址库命中结果：交易所、验证者、黑名单、观察等

路径明细怎么看：点层级里的「路径明细」就在该行下面展开这条线索的逐笔转账，每跳一行，从左到右是：跳号 → 路径（付款地址 → 收款地址）→ 流向/类型 → 金额 → 时间（北京）→ 区块。

  • 「流向」是相对路径方向说的：转出 表示资金顺着路径往下走，转入 表示这一跳是对方转过来的（资金反向），所以看路径时不用自己反推。
  • 「类型」里 转账 是普通 TAO 转账，stake#14 表示子网 14 的 stake 转移。
  • 地址显示为头 4 + 尾 4（和主表同一套规则），悬停可看完整地址，点击在 Taostats 打开。
  • 收起来有两个入口：明细右上角的绿色「收起明细」按钮，以及超过 3 跳时明细底部的同款按钮（长路径不用滚回顶部）。收起后层级里的按钮会变回浅色「路径明细」。

排序规则：交易所地址永远排最前（官方名单和人工确认的都算），公共地址排第二，其余按「关联强度」从强到弱排；同强度内层级浅的在前，再按累计金额。

强度是怎么算的（全部可解释，鼠标悬停能看到具体依据）：

档位 条件（累计与该起始地址的转账额）
极强 ≥ 1000 TAO
强 ≥ 100 TAO
中 ≥ 30 TAO
弱 有转账但没到 30 TAO
  • 往来 3 笔以上 升一档（极强封顶）——多次小额往来往往比一次偶然的大额更能说明关系。
  • 2 跳及以上 的间接关联降一档，最低到「弱」：隔着别人的地址，不该和直接对手方同档。
  • 如果这两个地址分属不同的地址库，会用两个库之间的历史累计规模做同档内的微调（最多 +8 分），不改变档位。
  • 这里的"库间规模"只统计本机已经抓到过的转账，不是链上全量，所以只当排序参考用。

用 层级筛选 可以只看 1 级（最可信的直接关系），或看全部。表格上方的“数据范围与限制”会写清这次用了哪个数据源、覆盖到哪个区块、有没有部分结果。

移除误判的关联后：点「刷新结果」

结果表每一行的「移除关联」只是把这条记录从当前表格里拿掉，不会立刻重新查询。确认这条线索不该出现时，点「关联地址」面板标题右侧的 「刷新结果」——按当前设置重查一遍，被移除的地址以及它的下游线索都不会再出现；重新扫描会恢复全部关联。

  • 按钮就在结果表上方、筛选项左边，字比较大、深青底白字，是这一块的主操作；按下去会有明显的下沉手感。
  • 有手动移除时按钮文案变成「刷新结果（已移除 N）」，外面带一圈呼吸涟漪，提醒"还有移除没生效"。
  • 只想反悔某一条：重新扫描即可全部恢复，移除只是当前这次查看的临时动作。

金额筛选：滤掉「轻微关联」

关联地址多起来时，很多是只转了几十块甚至零点几个 TAO 的地址，层级筛选没法把它们去掉。用「关联地址」面板右上角的 金额筛选 可以按 流入 / 流出 TAO 设门槛，只留下金额足够大的关联：

筛选口径 保留的地址
不限 全部关联地址（默认）
流入或流出 ≥ 流入或流出任一方向达到阈值（最常用，能同时抓住只收钱和只给钱的地址）
流入 ≥ 从这个地址收进来的金额达到阈值
流出 ≥ 从这个地址转出去的金额达到阈值
累计 ≥ 流入 + 流出 的合计金额达到阈值
流入且流出 ≥ 两个方向都达到阈值（只看双向都有实质往来的强关联）
  • 阈值填在右侧的 TAO 输入框里，输入即时生效（约 0.25 秒防抖），不用点按钮。只填数字没选口径时，自动按「流入或流出 ≥」处理，避免填了没反应。
  • 筛选后表格下方会显示「已按金额筛选隐藏 N 条轻微关联（显示 X / Y 条）」，告诉你一共滤掉了多少条；表格里的「关联地址」计数也是筛选后的数量。
  • 筛选只影响表格显示和「导出地址 TXT」（导出的就是筛完的干净清单），不会重新查询、不消耗 API；「导出 JSON」仍是完整记录，方便回看被筛掉的地址。
  • 筛选条件和层级筛选可以叠加使用（例如「只看 2 级」+「流入 ≥ 10 TAO」）。点 重置 恢复全部显示；选择会记在当前浏览器，下次打开还在。

六、导出与查询记录

导出

结果出来后，右上角有一个「导出层级」下拉和两个按钮：

  • 导出层级：可选全部层级 / 仅 1 级 / … / 仅 10 级——只导出指定层级的关联地址（和结果表「层级筛选」的口径一致）。比如只想要直接往来的 1 级地址，选「仅 1 级关联」再导出即可。
  • 导出地址 TXT：每行一个地址，方便直接粘到别的工具。会自动排除已确认的交易所和验证者地址，不用你再手动筛；文件名会带层级标记（如 -d2 表示只含 2 级）。
  • 导出 JSON：结果快照，包含层级、金额、标签等字段，适合存档或二次处理；同样按所选层级过滤。
  • 某个层级没有可导出地址时会明确提示，不会静默导出空文件。

查询记录（忘导出也不怕）

左侧菜单 查询记录 保存了每一次查询的完整结果——分轮跑完的、中途停止的、失败的、单轮查询的都在，最多保留最近 500 条。

「完成时间」按北京时间（东八区）显示，跟墙上的表对得上；分轮查询花的时间较长，这里记的是这一轮查询结束的时刻。失败的查询也会留一条记录，点「查看结果」会直接告诉你失败原因，方便对照「我确实查过、只是没查出东西」。

在这里可以：

  • 查看结果：回到扫描页，展示那次查到的地址，筛选和导出照常可用
  • 导出地址 / 导出 JSON：规则和当前结果完全一致，并按工具栏上的「导出层级」下拉分级导出（全部 / 仅 1 级 / … / 仅 10 级）
  • 同步地址库：把这次结果的关联地址 + 发起地址一次性写进已知地址库
  • 删除 / 清空：删掉不需要的记录

批量补录（找回升级前的结果）

0.3.0 之前的版本不保存查询记录，那些结果无法还原（当时只存在浏览器页面里，刷新就没了）。

如果你还记得当时查过哪些地址，在“查询记录”页顶部的 批量补录 里：

  1. 粘贴多个地址，每行一个；
  2. 点 开始补录，工具会按当前设置逐个重跑并自动存进查询记录；
  3. 进度条会显示成功/失败数量，可随时停止。

重跑结果按现在的链上数据计算，和当时可能略有差异。

七、已知地址库

左侧菜单 已知地址库 是工具的“常识库”：地址被标成交易所、验证者或公共地址后，查询时才能过滤、才能在结果里显示标签。

分类含义

分类记录“这个地址是谁”。预置三类，可以自己加（例如项目方、做市商，最多 12 个字）：

分类 含义 说明
大V 有影响力、值得重点关注的钱包 自己定义标准即可
群友 从群里、社区里收集来的钱包 自己定义标准即可
其他 暂时没有归类的地址 默认分类
自建 点下拉里的「＋ 新建分类…」或在地址库页“新增分类”创建 随时加、随时删

另外两个是系统分类，不用手工选、也不会出现在分类下拉里：

系统分类 来源 用途
EXCHANGE（显示为“交易所（系统）”） “确认交易所”按钮、同步官方名单 查询时勾选“过滤交易所”就会排除；确认后会自动校正旧结果里它的下游
VALIDATOR（显示为“验证者（系统）”） 验证者名单、「同步验证者地址」按钮、内置固定名单 查询时查到即截止，不再向下展开；勾选“过滤验证者”连它本身也排除；同步名单后会自动校正旧结果
PUBLIC（显示为“公共地址（系统）”） “标为公共地址”按钮、内置固定名单 查询时勾选“过滤公共地址”就会排除；不勾选时仍然作为关联终点（查到即截止，不再展开）；标记后会自动校正旧结果

公共地址：和交易所同性质的“汇聚型”地址

中转地址、发币池、公共充值地址这类账号，会和成百上千个互不相关的钱包发生往来。把它们标成公共地址后，查询时一旦查到就立即截止，不再从它继续往外扩展——否则结果会被噪音灌满，也会白白多花 Taostats 请求额度。

  • 标记入口有两处：扫描结果里关联地址行的「地址库」列，以及 已知地址库 清单展开后的同一列，点「标为公共地址」。
  • 标记只是往多分类里追加 PUBLIC，不会改你原来的分类 / 组名 / 备注；想撤回点同一位置的「取消公共标记」，只移除 PUBLIC。
  • 结果里这类地址会带琥珀色的「公共地址」标签，排序排在交易所之后、其他地址之前。
  • 想连它本身也不看，就勾选查询页的 「过滤公共地址」。

升级提示：旧版本的 WATCH / SEED / BLACKLIST 已不再使用，升级后这些地址会自动归到「其他」，不用手工改。

验证者地址：同样“查到即截止”

验证者的热钱包 / 冷钱包每天都在做押注、解押、子网质押，流水又多又碎，和几十上百个钱包都有往来。如果顺着它继续展开，一次查询很快会被这些无效关联灌满。

  • 带 VALIDATOR 分类的地址（人工标记、官方名单同步、内置固定名单三种来源都算）在查询时一旦查到就作为关联终点，不再向下扩展，和交易所、公共地址同口径。
  • 想连它本身也不看，就勾选查询页的 「过滤验证者」。
  • 验证者热/冷钱包会同时进库（Taostats 名单里两者都有，含各子网的 hotkey），所以一次同步新增 1000 条上下是正常的，都归在「验证者（系统）」分类里、清单折叠显示，不影响查询速度。
  • 随版本预置了一份验证者名单（app/data/builtin_validators.txt，约 1200 个地址）。它和「同步」的作用一样，但不需要联网、不需要 API key：远端机器 clone 下来启动服务，直接就有这 1200 个终点。想要更新的名单，就在能联网的机器上同步一次，把文件替换掉再升版本。

内置固定名单：人工核实的地址随版本预置

人工核实过的交易所、验证者、公共地址写在程序里（app/builtin_addresses.py），每次启动自动补进地址库，不依赖 Taostats 有没有配置 key：

  • 来源列显示「内置固定」，判定列显示「内置固定 · 不可改判」。
  • 这些记录不能删除、不能改分类、不能改判（单条删除会提示拒绝，批量删除自动跳过，解散地址库时也会保留）；名称和备注仍然可以自己改。
  • 如果同名地址你早就整理过（例如标成了「大V」或放在某个自建库），会保留你的分类、名称和所属库，只额外补上系统身份。
  • 升级后新增的固定地址在下次启动时自动出现，不需要做任何操作。
  • 验证者名单单独放在 app/data/builtin_validators.txt（一行一个地址，# 开头是注释），改了它下次启动就生效；交易所/公共地址仍在 app/builtin_addresses.py 里。

地址库清单：分组折叠 + 组内分页

地址库可能上千条（光预置验证者就 1200 条），所以清单是先分组、再分页：

  • 每组标题后面显示这一组的总条数，点标题展开/收起；
  • 展开后每组按 50 条一页显示，底部有「首页 / 上一页 / 下一页 / 末页」，标题里的条数始终是整组数量，不是当前页；
  • 「全选本组」按整组生效（不是只选当前页），勾选状态翻页不会丢，删除、导出选中都按整组选中的结果算；
  • 翻页不会把组重新收起；切换「按地址库筛选」会重建分组，页码回到第 1 页。
  • 清单工具栏还提供 搜索框（匹配地址 / 名称 / 地址库 / 备注 / 角色，输入即筛）和 角色筛选（公共地址 / 交易所 / 验证者），三者可叠加，命中数实时显示「N / 总数 条」；想定位某条标记过的地址（比如刚标为公共地址的那条）直接按角色筛最快。
  • 系统角色地址不会进用户自建库：把某个地址标为公共地址 / 确认交易所后，它会归入对应的系统身份分组、并从任何用户自建库（如查询时「新建地址库并导入」生成的库）里移出；新建地址库、导出地址 TXT 也会自动剔除交易所 / 验证者 / 公共地址，不会和系统分组混在一起。

确认之后，回头校正旧的查询结果

“查到即截止”只对之后的查询生效。以前查的时候这些地址还没被认定，工具把它们当普通钱包继续往下走了，旧结果里就留着一整片交易所/验证者/公共地址的下游噪音。确认之后可以回头把这些清掉：

自动发生的（不用你操作）： - 点「标为交易所」确认、点「标为公共地址」标记； - 在备注或标签里写上「交易所」； - 改某条地址的分类； - 点「同步官方交易所地址」或「同步验证者地址」（这两个一次会带进成百上千个终点）。

完成后，提示里会补一句「已顺带校正 N 条历史结果（移除 M 条无效关联）」。

手动全量校正：已知地址库工具栏的 「校正历史结果」。它先预演一遍，把「多少条记录、多少条无效关联」摆出来，你确认后才真正落库；没有可清理的内容就直接告诉你「已经是干净的」。

校正口径与实时查询完全一致： - 每条关联都看逐跳路径，路径前面出现过交易所/验证者/公共地址，说明它是从终点继续往下走出来的，删掉； - 老记录没有逐跳路径时，退回用中转图判断「是不是只能经过终点才能到达」——整条下游链一起删，绕开终点也能到达的地址保留； - 没有确凿证据的一律不删，只在报告里提示「另有 N 条无法确认，建议重查」，避免误伤正常线索。 - 终点地址自己永远保留（它是有价值的关联对象），被删的只是终点下游。

顺带清理的还有地址库侧的产物：巡检候选里由这些地址触发攒出来的线索会删掉，自动入库流水里由它们触发的记录标成「已撤回」（否则交易所/验证者的往来会继续把它们自动写回地址库）。地址库里的地址本身不会被删除。

校正过的查询记录会在「查询记录」页的关联数上体现（数字变小），重新导出也是校正后的结果；结果页顶部的提示区会写明这条记录被移除了多少条。

判错了随时改：交易所结论可以来回切换（官方名单除外）

人工确认或否定交易所之后，结论不是“一锤子买卖”，任何时候都能改：

当前位置 按钮 点完的效果
已确认交易所 改为否定 / 重置为待确认 判错了？改成否定；或清掉人工结论回到“疑似交易所（待确认）”
已否定交易所 改为交易所 / 重置为待确认 否定错了（后来核实确实是交易所）就点这个，立刻变回确认
待人工确认 确认交易所 / 否定交易所 第一次下结论
  • 两处都能改：扫描结果里每个关联地址行的「地址库」列，以及 已知地址库 清单展开后的同一列。
  • 只有“人工判定”的交易所可以改判。 从官方交易所名单同步来的地址会显示成 官方交易所 · 不可改判，没有改判按钮；来源列显示「官方交易所名单」。这类记录的分类、名称、备注也都固定，备份还原、文件导入同样不能把它改回“待确认/已否定”。
  • 改判不会冲掉你起的组名：以前在结果表里点确认/否定会把名字改写成“人工确认交易所 / 人工否定交易所”，现在只有名字为空或本来就是这两个自动名时才替换，自己起的名字（例如“某交易所·热钱包”）保持不动。
  • 确认后该地址会作为关联终点（刷新结果后其下游不再展开）；否定后不会被交易所过滤，也不会再被列为候选。两种状态都还能再改。

组内手动添加地址

地址库清单里每个标签组展开后，表格上方有一个 「＋ 手动添加地址」 按钮：

  1. 点开后在输入框里粘贴地址，每行一个，也支持逗号 / 空格分隔（单次最多 200 个）；
  2. 备注选填，只会写给这次新加的地址；
  3. 点「添加到本组」即可。

加进去的是当前这一组：自建库带库名，标签组带组名，分类跟随该组；格式不对的地址会逐个提示。加错了点工具栏 「撤回上次导入」 可以整体撤销。

地址已经在别的组？ 默认不会搬动它——保存后会提示“1 个已在「rrik」组，已跳过”。这时勾选输入框里的 「已在别的组的地址也移到本组」 再点一次，就会把它从原组转过来（改它的组名和分类，备注保留，同样能用「撤回上次导入」退回原组）。

注意「人工确认交易所 / 人工否定交易所」两个组：这两个组名本身就是结论，往里加地址（或把地址转进来）会同时把该地址标为已确认 / 已否定的交易所，扫描时立即按这个结论过滤。要改结论仍可用行内的「改为否定 / 改为交易所」。

合并群组

同一个种子扫出来的地址，有时会被分到几个库里、互相交叉命中（比如 A 库和 B 库都在反复出现同一批人）。与其逐条删了重导，可以直接把它们并成一个库：

  1. 地址库清单工具栏点 「合并群组」，下方展开合并面板；
  2. 勾选两个以上组（自建库、人工命名的标签组都可以；未命名的分类兜底组不参与，避免误并）；
  3. 选择名字： - 起个新名字：填一个没被占用的名字，合并后是一个新的自建库； - 沿用已有组名：从所选组里挑一个，合并后继续用这个名字（该组原来的库直接扩大）；
  4. 点 「合并（N 组 / M 个地址）」，确认框会列出所有来源组和合计数。

合并只改“归属”，每条地址的分类、备注、交易所人工结论都原样保留，地址本身也不会重复（地址在库里唯一）。合并不满意就点工具栏 「撤回上次导入」，一次退回原来的分组，被并掉的库名也一并恢复。

目标名不能和别的（未参与合并的）地址库重名——这种情况会被拒绝，避免把不相干的库连人带地址吞过来。

关联明细检索：这两个地址到底有没有来往

关联扫描回答的是“谁和谁有关系”，但有时你只想知道两个具体地址之间有没有直接发生过转账，或者某个地址跟你地址库里的谁有过往来。地址库页面顶部的「地址关联明细检索」专门干这件事。

用法一：地址 A × 地址库

  1. 「地址 A」填一个地址；
  2. 「比什么」选 和地址库比，右边选一个自建库或标签组（例如 6NCK）；
  3. 「最多跳数」默认 3（最高 10，和关联层级同一个上限），「最低 TAO」随意，「翻页上限」决定往回翻多少页历史（1–10，默认 3）；
  4. 点 「开始检索」。

结果会列出这个地址和库里哪些地址真的发生过转账，以及每一笔的时间、方向、金额、区块和交易哈希。

用法二：地址 A × 地址 B

「比什么」切到 和另一个地址比，填地址 B。系统先精确查这两个地址之间的直接转账；如果没有直连，就顺着双方各自的流水找中间地址，拼出 A → 中间地址 → … → B 的链路（最长跟「最多跳数」一致，最高 10 跳），每一跳都标金额和时间。

结果怎么看

  • 最上面一条是统计：命中地址数、转账笔数、关联链路数、这次花了多少次请求（缓存命中不算）。
  • 「有往来的地址」按往来金额排序，看流入 / 流出 / 笔数 / 最近一次。
  • 「转账明细」按时间倒序，方向是相对地址 A 说的：流出 → 表示从 A 转给别人，← 流入 表示别人转给 A。
  • 「来源」列写明这笔是本地索引还是 Taostats 查到的；同一笔不会重复统计。

关于请求次数

Taostats 有本机限速（5 次请求/分钟）。一次检索最多花满这个额度，用完不会报错，而是把已经查到的部分先给你，顶上标注「结果可能不完整」；等一分钟再点一次「开始检索」就能接着查。已取到的分页会缓存 5 分钟、不重复计费，所以多点几次比一次翻很多页更快：找 8 跳链路第一轮通常只能展开到 3 跳左右，第 2–3 轮就会拼出来。想查更深的历史，把「翻页上限」调大（每页 200 笔，最高 10 页）。

提示：本地索引只覆盖本机采集过的区块，历史明细基本都来自 Taostats，所以请先在扫描页配好 API key。

管理分类

在 已知地址库 页的“分类”面板里：

  • 每个分类显示当前地址数；自建分类带 删除 按钮，删除后该分类下的地址自动回到「其他」，地址本身不会丢。预置分类（大V / 群友 / 其他）不能删。
  • 结果页、查询记录页的分类下拉最后一项是「＋ 新建分类…」，选中后输入名字即可就地新增，不用专门跑到地址库页。

添加与导入

  • 单个添加：填名称、分类、地址、备注，点“添加地址”。
  • 批量导入文件：支持 TXT、CSV、JSON，点“导入文件”选择。旧文件里的 WATCH / SEED / BLACKLIST 会自动折算成「其他」；只写地址、不写分类的文件不会改动已有地址的人工分类。
  • 标签（标签组）：不填名称时默认取地址后四位，清单里以虚线弱化显示；自己起过名的标签是自定标签，两种样式一眼能区分。地址库清单按标签归并成组，同一组里可以有不同的分类。
  • 同步官方交易所地址：官方名单默认导入——每次启动服务时后台自动同步一次（需要已保存 API key），运行期间不再自动请求；想立刻刷新名单再点这个按钮。
  • 只增不改：名单里没见过的地址才会新增；已在库里的地址（比如你手工标成「大V」的）保留原来的分类、名称、备注和所属地址库，只把“交易所（系统）”补进它的分类并锁定判定。
  • 同步完会提示这次新增了哪些地址（名称 + 地址后四位）；一个都没新增时提示“名单已是最新”。开机自动同步的提示只出现一次，点过之后不再重复弹。
  • 官方名单里已经删掉的地址不会从你的地址库里删掉，避免误删整理好的数据。
  • 按钮下方一行小字显示当前官方条数和最近同步时间。
  • 同步验证者地址：紧挨「同步官方交易所地址」。调用 Taostats 活跃验证者名单，把当前在跑的验证者热/冷钱包写进地址库（分类 VALIDATOR），同步完提示新增了多少个。
  • 如果提示「验证者名单请求失败：…SSL: UNEXPECTED_EOF_WHILE_READING」，那是和 Taostats 的 TLS 握手偶发被截断，不是 key 有问题。程序会自动退避重试 3 次（约 3.6 秒内）；3 次都失败才会报错，这时直接再点一次即可，不需要改设置。
  • 同样只增不改：已在库里的地址保留原分类、名称、备注，只追加「验证者（系统）」；名单里消失的地址不删除。
  • 同步进来的地址查询时查到即截止，不再向下展开，避免验证者流水把结果灌满无效关联。
  • 不点这个按钮也没关系：内置固定名单里的验证者、以及你手工标记过验证者的地址同样会终止关联。
  • 从查询结果同步：在结果页的“同步到已知地址库”里选好分类和标签，把整批关联地址 + 发起地址去重写入；已在库里但还挂在「其他」上的地址会按本次选择的分类归位，已经人工分好类或系统分类的记录不会被覆盖。
  • 从查询记录同步：查询记录页顶部可以设置“同步分类 + 标签”，点某条记录的「同步地址库」时就按这组设置写入。

地址库巡检：新地址自动入库

地址库页面上方有一块 地址库巡检。打开后，工具会按设定间隔挨个检查库里每个地址的新转账（含子网 stake 代币转移），发现以前没见过的对手方就按规则自动入库，并写一条入库日志。

判定规则

  • 触发条件：单笔 ≥ 阈值 或 与该地址的累计 ≥ 阈值，任一满足即入库。阈值默认 30 TAO，可改。
  • 归属地址库：同一个新地址被多个库触发时，按累计转账金额最多的那个库入库；金额相同比笔数。先入库、后来又发现另一个库累计更高时，会自动改判到金额更高的库，并在日志里写明"改判"。
  • 只认新发生：第一次检查某个地址时只记录基线区块，不会把它历史上的对手方一次性灌进库；之后只处理基线之后的转账。
  • 不参与巡检：交易所、验证者、「系统」分类的地址，以及（默认）自动入库的地址。这样不会顺着转账一层层无限扩散。

参数

参数 默认 说明
开启巡检 开 关掉后完全不再自动请求
阈值 TAO 30 单笔或累计达到就算一条新地址
间隔 每天 每轮把库里地址过一遍；一轮可能跑几小时，跑不完第二天接着轮转
每日请求上限 700 到点就停，保护你的 API 额度
含代币转移 开 每地址多 1 次请求；只想要 TAO 转账就关掉
跟踪自动入库地址 关 打开后自动入库的地址也会被巡检，会一层层扩散，慎用

额度要有心理准备：每个地址每轮 1~2 次请求。库里 690 个可巡检地址时，一轮约 690~1380 次请求；按免费档 5 次/分钟算，要跑 2.3~4.6 小时。所以界面上显示"本轮已查 N 个"，不是几秒钟就能跑完。

和手动查询会抢额度吗？不会了（0.8.11）

巡检和手动查询共用「每分钟 5 次」这条本地保护线，以前是先到先得：巡检按固定节奏占着约 4 次/分钟，你点查询时常常只剩 1 次，一轮跑不满还要反复等 62 秒。现在改成手动查询优先：

  • 只要有查询任务还没结束——包括每轮之间那 62 秒等待——巡检就跳过本轮（每 30 秒判一次），不占配额。把等待期当空闲是错的，那 62 秒里巡检一插进来，你下一轮又要重新等。
  • 查询出结果后，再等 2 分钟没有新的查询，巡检才继续。
  • 巡检面板会显示「已让路：手动查询进行中」或「已让路：查询已结束，冷却 N 秒」。看到巡检进度停住不用怀疑它坏了，是它主动让开的。
  • 让路只让时间、不让额度：每日 700 次只统计巡检自己发的请求，手动查询用的不算在这本账里，所以不会因此少查地址，只是整轮顺延。
  • 兜底：如果某个查询任务卡住超过 10 分钟没有任何进度（状态、轮次、请求数、待查队列全都不动），会按"僵死"处理并恢复巡检，避免后台永久停摆。

入库日志

点 入库日志 展开，每条记录写清：新地址、金额、笔数、类型（转账 / 代币转移）、归到哪个库、触发地址、以及"为什么归这个库"（各库累计对比）。

  • 每条都能 撤回：自动写入的地址会被删掉，同时把这个地址拉黑，之后巡检不会再收它。
  • 你手工添加或改过分类的地址不会被删，只停止自动入库。

注意：自动入库会带来噪音（交易所热钱包、机器人、一次性中转）。发现有价值的库被灌脏了，直接撤回那几条即可；也可以把阈值调高。

新建地址库并导入（给一批关联地址起个名字）

查了一个新地址、结果里一个已知库都没命中时，可以在结果区的 “或：新建地址库并导入” 里给这批结果建一个自己的库：

  1. 在 地址库名称 里填一个名字（最多 60 个字，例如“2026-11 疑似同一实体”）。
  2. 需要的话改分类（大V / 群友 / 其他 / 自建分类），默认「其他」；下拉里也能就地新建分类。
  3. “包含发起地址”默认勾选，会把查询用的起始地址一起写进库。
  4. 点 新建地址库并导入。工具会自动剔除已人工确认的交易所地址和验证者地址，和“导出地址 TXT”的规则一致；按钮上方的提示会实时显示“本次可导入 N 个地址”。

几点说明：

  • 同名库重复导入只补新地址，已有记录的分类、标签、备注都不会被改；已经属于其他库的地址会保留原库，不会被打包抢走。
  • 地址库页顶部会出现 “自建地址库” 卡片，显示每个库的地址数、来源发起地址和创建时间；可以“只看此库”、整库导出 TXT/CSV，或 解散（库名和库里的地址一起删除，误删可点「撤回上次导入」恢复）。
  • 地址库清单里多了一列“地址库”，工具栏也能按库筛选；导出 CSV/JSON 和导入文件都支持 book 字段，换电脑迁移时库归属不会丢。
  • 外发包自带预置地址库（app/seed_books 里每个 TXT 文件就是一个标签组，文件名即组名）：第一次启动自动装进已知地址库，装过之后重启不会重复导入，也不会覆盖你手工改过的地址。
  • 如果解散了预置组、或误删了其中地址，点工具栏的 「重新导入预置库」 就能补回来：只补地址库当前缺失的地址，已存在的跳过，不覆盖你改过的分类 / 标签 / 备注；解散过的组会连库带地址重建。导错了同样用 「撤回上次导入」 撤销。
  • 地址库清单每个标签组标题右侧有 「全选本组」：一次选中该组全部地址（组内部分选中会显示半选状态），再点工具栏的 「删除所选」 即可整组处理。
  • 删除前都会先弹确认框，并把对象写清楚：单条删除显示地址（前后各四位）、名称、所属地址库和分类；批量删除会按组列出“某组 N 条”。解散地址库可以「撤回上次导入」恢复，单条和批量删除不可撤回，删之前建议先导出 TXT/CSV 备份。

改名与撤回

  • 整组改名：点标签组标题右侧的 ✎（改名） 按钮，输入新名字后按回车（Esc 取消）。改名会把这一整组地址的标签一起改掉，方便把默认后四位改成像「项目方A」这种能识别的名字；自建地址库改名会同时改库名和库内全部标签。
  • 整组改分类：点标签组标题右侧的 「改分类」，勾选后保存，这一组的全部地址一起换成这组分类。默认只勾该组当前的主分类：勾一个 = 整组替换；勾多个 = 这组地址同时属于多个分类。交易所 / 验证者地址会自动跳过，不会被冲掉身份。
  • 单条只改备注：某一条地址的身份说明写在这个地址行右侧的「备注」里，不单独改标签或分类——标签和分类都代表"这一批是谁"，单条改会把整组拆散。
  • 撤回上次导入：工具栏的 「撤回上次导入」 会撤销最近一次批量写入（同步地址库 / 新建地址库 / 导入文件 / 重新导入预置库）：删除那次新加的地址，把被改写的分类、标签、备注、所属库还原，新建出来的库也一并移除。只保留最近一次，撤回后按钮变灰。

九、本地索引（进阶，可跳过）

页面中间有一块 更新链上索引：

  • 扫描最新：抓取最新已最终确定的若干个区块，把里面的转账事件存进本地数据库；
  • 继续水位：从上次停下的区块继续往后扫，避免重复。

本地索引的好处是不消耗 API 额度；缺点是只包含你实际扫过的区块。公开节点会裁剪历史状态，所以不能指望靠它拿到全链历史。日常查关联建议直接用 Taostats 数据源。

服务启动后，本地索引会每 5 分钟自动往后扫 16 个新块（约 3 分钟链上时间），不需要你手动点。它只补"启动之后"的新块：关机久了留下的缺口不会自动补，需要的话手动点「继续水位」多扫几次。想关掉自动扫描，可以在配置里把 LOCAL_AUTO_SCAN_ENABLED 设为 False。

十、拷贝到另一台电脑

只是同一台电脑换个磁盘/目录再装一份做测试？不用看这节，按 四、启动 里“在同一台电脑上复制一份做测试”操作即可，不需要重装也不需要重签授权。

下面说的是换电脑：目标电脑上没有这套运行环境，所以要重新安装，而且机器码会变、需要重新激活。

这个文件夹是可以整体搬走的，但运行环境不能直接搬。正确做法：

  1. 在旧电脑双击 停止.cmd 关闭服务；
  2. 把整个文件夹复制到新电脑（U 盘、网盘都行）；
  3. 在新电脑进入文件夹，双击 安装.cmd； - 脚本检测到 .venv 失效会自己重建，不需要你手动删除； - 如果新电脑没装 Python，脚本会尝试自动装，见 三、安装；
  4. 装完双击桌面快捷方式即可使用。

注意：授权码和电脑绑定，拷到新电脑后需要重新激活（新电脑页面会显示新的机器码，找管理员要一个新授权码即可）。license.key 拷过去也不会被认。

数据要不要一起带走

文件夹 内容 建议
data\ 地址库、查询记录、本地索引数据库 想保留历史就一起拷；想从空白开始就删掉，启动时会自动重建
logs\ 运行日志 可不拷
.venv\ 运行环境 可以不拷（会自动重建），拷了也没问题

注意：data\ 里有你查过的地址记录，如果把文件夹发给别人，建议先删掉 data\。

用 GitHub 同步到另一台电脑

用 git clone / git pull 拉下来也是同样的道理，但有两个地方要注意：

仓库里不包含运行环境和数据。 .venv/、data/、logs/ 都在 .gitignore 里，拉下来只有代码。所以：

  1. 拉完代码，双击 安装.cmd 重建运行环境（没装 Python 会提示你怎么装）；
  2. 双击 启动.cmd；
  3. 授权码绑机器，新电脑要重新激活。

如果这台电脑之前改过脚本，git pull 会冲突。 冲突没解决时，脚本里会残留一排 <<<<<<< HEAD 之类的标记，PowerShell 会把它当成保留运算符，报 The '<' operator is reserved for future use——这个报错跟真正原因无关，很容易看懵。0.6.26 起，启动.cmd / 安装.cmd 会先检查这种情况，直接告诉你怎么办。

手工修也很简单，在文件夹里打开命令行：

git status
git checkout origin/main -- start.ps1 launch_desktop.ps1

本地没有要保留的改动时，把整份工作区对齐到远端最省事（data/、logs/、license.key 都不受影响）：

git fetch origin
git reset --hard origin/main

最容易踩的坑：拉完代码没有重启服务。 git pull 只改了硬盘上的文件，正在跑的那个进程还是旧代码。而且旧版本页脚显示的版本号读的是硬盘上的 VERSION 文件——所以你看到「0.7.7」「0.7.8」更新了，实际跑的可能是几天前的 0.7.6，功能自然还是旧的（典型症状：地址库里没有预置验证者、点同步还是报错）。

0.7.8 起不用记这件事了：再双击一次 启动.cmd，脚本会自己比对「运行中的版本」和「硬盘上的版本」，不一致就打印一行

检测到代码已更新：运行中 0.7.7 → 磁盘 0.7.8
正在重启服务以加载新版本…

然后自动停掉旧进程再重新启动。用更早的版本时，必须先双击 停止.cmd，再双击 启动.cmd；只关浏览器标签不算，服务还在后台跑。

改完还不确定生效没有，打开页面左侧的 「更新日志 → 环境自检」 点「运行自检」，五项一次列清：代码版本、预置验证者文件（多少条、什么时候改的）、有没有真的写进地址库、本次启动写了几条、API key 状态。哪项没通过，下面直接写着这一步该做什么。不想开浏览器就在文件夹里执行：

.\.venv\Scripts\python.exe run.py --doctor

它不开服务，直接把同样的结论打印到窗口里，退出码 1 表示有项目没通过。

十一、多设备访问

手机、家里的另一台电脑、公司电脑，都想打开这套工具： 只待在家里用 → 「做法一」，同一个 Wi-Fi 就能开； 想在外网用、客户端又不想装任何软件 → 「做法二：公网隧道」； 主机重启后地址会不会变 → 「主机重启 / 关窗口之后，隧道地址会不会变？」

先说结论：让一台电脑跑服务，其他设备只开浏览器访问。不要在每台电脑各跑一份再同步地址库——那样会互相踩死，原因见下面「为什么不能两台各跑一份」。

做法一（推荐）：一台主机跑服务，其余设备当客户端

在那台尽量常开的电脑（下面叫「主机」）上，双击 启动-远程访问.cmd（想用命令行就是 python run.py --remote）。

启动窗口会打印一个小面板，包含访问口令和各设备该用的地址：

 访问口令   ABCD-EFGH-IJKL-MNOP   ← 本次新生成
 本机       http://127.0.0.1:8766
 Tailscale  http://100.101.102.103:8766
 局域网     http://192.168.1.20:8766
  1. 家里 / 公司 / 手机浏览器打开面板里对应的地址；
  2. 第一次会要求输入访问口令，输一次记住 90 天，之后不用再输；
  3. 只有主机需要激活授权——其他设备只是浏览器在调主机的接口。

窗口关掉也不丢：口令和面板都在 logs\wallet-link.stderr.log 里。 双击 启动.cmd 仍是原来的「只允许本机」模式；两种模式随时切换，切换时脚本会自动重启服务。

访问口令是什么：--remote 会把服务从「只听本机」放开到「全网卡」，同一个 Wi-Fi 或同一个 Tailscale 网络里的人就都能打开页面、用你的 key、改你的地址库。所以加了一道门：主机本机（127.0.0.1）打开免验证，从别的设备进来必须带口令。

  • 口令首次自动生成，存在 data/settings.json，和备份一起搬走；
  • 想看口令：在主机浏览器控制台或页面接口里查，终端启动面板也会打印；也可以在主机上 curl http://127.0.0.1:8766/api/access/token；
  • 想换口令：主机上 POST /api/access/token/rotate，旧口令连同所有已登录设备立即失效；
  • 口令只能在主机上查看和重置，远程设备即使已经登录也不给看。

安全边界：口令是防「同网段的其他人误入」，不是防公网。不要把 8766 端口直接映射到公网——要在外网用，走下面的「做法二」，让隧道替你挡在前面。

做法二（外网访问、客户端零安装）：公网隧道

Tailscale 好是好，但每台手机、每台电脑都得装一遍。如果你只想「打开浏览器就能用」，用 Cloudflare 隧道：

  1. 在主机上双击 启动-公网隧道.cmd；
  2. 首次运行会自动下载一个约 30MB 的隧道程序（tools\cloudflared.exe，只需一次），同时以隧道模式启动服务；
  3. 窗口会打印一个 https://xxxx-xxxx.trycloudflare.com 网址和访问口令；
  4. 手机 / 外网电脑直接打开那个网址，输一次口令，之后记住 90 天。

需要理解的三件事：

  • 客户端不用装任何东西，但主机侧必须有个出口。家里宽带没有公网 IP，外网进不来，所以由主机主动向外连到 Cloudflare，请求顺着这条连接转回来。路由器全程没有接受任何入站连接，公网也看不到你的真实 IP。
  • 这是临时地址，关掉窗口就失效，重新启动会换一个新网址（免费、免注册、不限流量）。想要固定网址，需要一个自己的域名（年费几十元）托管到 Cloudflare，用「命名隧道」把 wallet.你的域名.com 固定指向 8766——客户端仍然只是浏览器，把 启动-公网隧道.cmd 换成开机自启的 cloudflared 服务即可。
  • 再加一道邮箱验证码：把邮箱作为参数传进去——启动-公网隧道.cmd 你的邮箱@example.com。这样即使网址被别人看到，只有那个邮箱能收到验证码进来。不需要注册 Cloudflare 账号。

隧道下的口令规则和局域网一样：只有真正坐在主机前的浏览器免口令；经隧道进来的一律要输口令（包括你在主机上用那个 https 网址打开自己）。这条如果有人改坏了，就等于把命令执行权限挂在公网上——tests/test_tunnel_access.py 专门锁死了它。

换成云服务器之后怎么办：把这份代码部署到服务器，用 Nginx + 域名 + 免费证书反代到 8766，客户端还是打开一个网址，什么都不用改。注意 API key 目前用 Windows DPAPI 加密存在 data/settings.json 里，搬到 Linux 服务器解不开，需要在服务器页面上重新粘贴一次 key。

主机重启 / 关窗口之后，隧道地址会不会变？

会变。 现在跑的是 Cloudflare 临时隧道（quick tunnel），网址在每次启动时随机分配：

  • 关掉那个窗口 → 网址立刻失效，别人再打开会看到 Cloudflare 的 502 页面；
  • 主机重启 → 服务和隧道都停了，再双击 启动-公网隧道.cmd 会拿到一个全新的网址，旧网址一律作废；
  • 就算不重启，隧道进程被杀、断网重连后重建连接，也可能换网址。

所以临时隧道适合「这几天自己用一下」，不适合「发给别人长期收藏」。想让网址固定，三条路：

做法 地址 代价
命名隧道 + 自己的域名（长期推荐） 固定，如 wallet.你的域名.com 一个域名（年费几十元；DNS 托管到 Cloudflare 免费）+ 一次配置
局域网 + 路由器给主机固定 IP 局域网内固定，如 http://192.168.1.20:8766 只在同一个 Wi-Fi 下有效，出门用不了
Tailscale 固定，http://100.x.x.x:8766 每台客户端都要装 App

主机重启后，服务不会自己起来。 两种情况要分开看：

  1. 服务本身：双击脚本才会启动，重启电脑后必须再双击一次（或在浏览器打开页面确认打不开，就知道了）。
  2. 隧道进程：跟着那个命令行窗口活着，窗口关了、机器重启了，隧道就断了。

想省掉"每次重启都要点一下"，按 Win + R 输入 shell:startup 回车，把 启动-公网隧道.cmd 的快捷方式拖进弹出的文件夹。这样每次开机登录后它会自己跑起来——但网址仍然是新的，起床后看一眼窗口里印的地址，重新发给需要的人（或者干脆一次配好命名隧道，从此不用管）。

为什么不能两台各跑一份

问题 后果
限速器是进程级的 两台各有一份计数器，都以为自己 5 次/分钟没问题，服务端看到的是同一个 key 合计 10 次/分钟 → 429。两边还都会显示「被限流」，看着像 Taostats 的问题
巡检会重复烧额度 每地址 2 次请求 × 685 个地址，两台各跑一遍 = 同一批地址查两次，产出为零、额度翻倍
SQLite 单写 两台同时写同一个文件会损坏；想「看到同一个库」只能访问同一个进程

一条不能违反的规则：同一把 Taostats API key，同一时刻只能有一台机器开巡检。 备机如果要装同一份代码做故障切换，务必把巡检开关关掉（config.enabled=false，tick() 会直接返回、一次请求都不发），等主机挂了再打开。

做法三（离线兜底 / 换电脑迁移）：导出 JSON 同步包 + 私有 git / U 盘

这不是日常协同手段，只在三种情况下用：主机长期不在线、换电脑迁移、备机离线跑完回灌。

  1. 在一台机器点「导出全部」（JSON），得到一个 schema_version=2 的同步包，里面每条地址都带 created_at / updated_at 时间戳；
  2. 把它提交进你的私有 git 仓库（GitHub 私有库 / 本地 git 都行，别用公开库），或拷到 U 盘；
  3. 另一台机器 git pull / 拷到本地后，在「批量导入文件」里选这个 JSON 导入；
  4. 导入会按时间戳做最后写入优先（LWW）合并： - book（所属用户库）取较新一方，且允许被较新的空值清空——这正好能修复“某台把公共地址移出用户库后，另一台残留旧 book 清不掉”的污染滞留； - label / note 取较新一方，但空值不覆盖非空，不会误清空人工备注； - categories 仍取并集（分类是附加信息，不丢数据），交易所锁定逻辑不变； - 没有时间戳的旧包（纯 TXT / 老 CSV）仍按原保守合并，行为不变； - 每次导入都记批次，导入错了点「撤回上次导入」即可还原。

两边各跑一次（A 导→B 导，再 B 导→A 导）就能把两份库合并成一致；因为按地址唯一合并，重叠地址不会变成重复行。

两条硬约束

  • SQLite 不要走网络文件系统共享（SMB / NFS 挂 data/wallet_link.db）。Tailscale 做法下只有一台跑服务、其余用浏览器，天然规避；别尝试把数据库文件直接放共享盘让两台同时写，会损坏。
  • git 只同步导出的 JSON 同步包，绝不同步 .db 文件——SQLite 二进制无法干净合并，提交它只会制造冲突和损坏。.gitignore 已把 data/ 排除，保持这样即可。

整理 / 修复污染（两种做法都适用）

两台机器的库反复互相导入后，即使地址不重复（地址在库里唯一），也可能残留一些“看着别扭”的脏数据。地址库清单工具栏点 「整理地址库」 可以一次修干净：

  • 会先弹出预览，告诉你“将修正 N 条、具体是哪几类”，确认后才落库；整理完可以点 「撤回上次导入」 整体还原。
  • 只做三类安全规整，不删地址、不改你的标签 / 备注： 1. 多分类脏数据：清掉多分类里“不在分类表、也不是系统分类”的孤立名，去重、超上限截断；主分类若没在多分类里会补回去；主分类为空则补「其他」。 2. 系统地址误挂用户库：交易所 / 验证者 / 公共地址 / 内置固定名单的地址，如果残留了「所属地址库」，会被清空——它们本该归在系统分组，不该混在你的自建库里。 3. 残留的交易所锁定标记：某条地址以前确认过交易所、后来分类改回了普通分组，确认标记却还在。整理会清掉这种脏标记；官方名单 / 内置固定名单的交易所结论一律不动。
  • 历史自定义分类（旧 CSV 导入时留下的、已不在分类表里的名字）不会被当成孤立项清掉，因为 categories() 会把“地址记录里出现过的分类名”视为合法，保护你原有的分类。

十二、常见问题

Q：启动时提示 The '<' operator is reserved for future use，或者满屏 <<<<<<< HEAD？ 这是 Git 合并冲突没解决，冲突标记留在 start.ps1 里了，跟程序本身没关系。在文件夹里打开命令行执行 git status 看哪些文件冲突，然后 git checkout origin/main -- start.ps1 launch_desktop.ps1 恢复成仓库版本即可。详见 十、拷贝到另一台电脑。

Q：升级到新版本后，地址库里还是没有预置验证者／点「同步验证者地址」还是报错？ 九成是服务没重启，跑的还是旧进程。先在「更新日志 → 环境自检」里看第一项「代码版本」：如果写着「磁盘上的 VERSION 是 X，但这个进程跑的是 Y」，就是这个问题，双击 停止.cmd 再双击 启动.cmd 即可（0.7.8 起再双击一次 启动.cmd 就会自动重启，不用先停）。自检里「预置验证者文件」如果显示「找不到」，说明 app/data/builtin_validators.txt 没拉下来（只拷了 app/*.py 之类的半份代码），重新 git pull 整个仓库或用完整外发包覆盖。两项都正常但库里仍没有，重启后看 logs\wallet-link.stderr.log 有没有 [builtin] 版本 … 预置验证者 1196 条；本次启动新增 … 这一行——有这行就说明新版本真的跑起来了。

Q：双击 安装.cmd 后窗口一闪就没了？ 说明安装过程中出错并退出了。重新双击一次，窗口最后会停住显示错误信息；把信息截图或复制下来便于排查。最常见原因是没装 Python 或网络连不上 PyPI。

Q：安装时提示“禁止运行脚本”？ 安装.cmd、启动.cmd 已经用 -ExecutionPolicy Bypass 绕过这个限制，正常不会出现。如果仍被拦，多半是公司电脑的安全策略，需要找 IT 放开。

Q：页面打开是空白 / 样式错乱？ 按 Ctrl + F5 强制刷新。版本更新后浏览器可能还在用旧缓存。

Q：提示端口被占用 / 服务起不来？ 8766 端口被别的程序占了。在文件夹的 PowerShell 里执行 .\start.ps1 -Port 8777，然后访问 http://127.0.0.1:8777。

Q：查询结果的地址是 0 个？ 0.6.4 起结果区顶部会直接列出原因（key 未配置、本地索引为空、金额门槛太高、过滤条件挡掉等）。常见处理：① 确认已保存 Taostats API key（勾着“使用 Taostats 历史索引”时没 key 会被直接拦下）；② 金额阈值改小（把 1 改成 0.1 试试）；③ 这个地址可能本来就没有往来。

Q：分轮查询到一半不动了？ 每分钟 5 次请求的限制会让每轮之间等约 1 分钟，属正常现象。如果超过 3 分钟没变化，点“停止续查”保留已有结果，稍后重试。

Q：手机 / 另一台电脑打开主机地址，一直要求输入访问口令，输对了也进不去？ 先确认输入的是主机当前这一版的口令——点过「重置口令」的话，旧口令会立即失效。在主机上执行 python run.py --remote，启动面板会打印当前口令；也可以主机上直接访问 http://127.0.0.1:8766/api/access/token 查看。仍然不行的话，检查是不是用了 http://127.0.0.1:8766 访问——127.0.0.1 在手机 / 另一台电脑上指的是那台设备自己，必须用面板里打印的 Tailscale 或局域网地址。

Q：从别的设备打开页面，提示「无法连接到服务」？ 逐项排查：① 主机是否还在跑（主机上打开 http://127.0.0.1:8766/api/health 看有没有返回）；② 主机启动时是不是没用 --remote——只监听 127.0.0.1 时外部设备根本连不上；③ 两台设备是否在同一个 Tailscale 网络（tailscale status 看两边是否都 online）；④ Windows 防火墙是否拦了 8766 端口（首次启动时弹出的允许提示要勾「专用网络」）；⑤ 主机休眠了——甲方案依赖主机在线。

Q：昨天那个 trycloudflare.com 网址，今天打不开了 / 提示 502？ 临时隧道的网址是每次启动随机分配的：关掉窗口、电脑重启、隧道进程重连，网址就作废。在主机上看一下当前窗口（或 logs\cloudflared.url 文件）里印的新网址，用新的打开即可。想让网址固定，需要按 十一、多设备访问 里「主机重启 / 关窗口之后，隧道地址会不会变？」的表格配命名隧道。

Q：巡检进度一直不动？ 0.8.11 起手动查询优先，巡检会主动让路：查询进行中（包括轮间 62 秒等待）以及查询结束后 120 秒内，巡检都不推进，面板会显示「已让路：手动查询进行中 / 冷却 N 秒」。这是预期行为。如果显示的是僵死提示，说明有条查询任务超过 10 分钟毫无进度，系统已按僵死处理并恢复巡检。

Q：点「扫描最新块」转很久没反应，或者提示「扫描失败」？ 0.8.10 起首次扫描要先从链上拉取 runtime 元数据（实测 30~90 秒，取决于网络），期间按钮会显示「扫描中（首次预热约 1 分钟）…」，不要重复点——重复点会提示“已有扫描在进行”。预热完成后每块只需几秒，完成提示里会附带「运行时预热 XX 秒」。如果失败信息是 RPC scan failed: TimeoutError: ...，说明节点或网络太慢，稍后重试即可；如果提示 409「a scan job is already running」，重启一次服务——0.8.10 起启动时会自动把上次被强杀留下的扫描标记为中断并释放锁，等 8 分钟租约过期的情况已经不会再有。

Q：查询提示「未配置 Taostats API key」，但我明明填过 key？ 先升级到 0.8.16 再看：0.8.15 及更早版本会把「连不上 Taostats」误报成「没有 key」。原因是那时出站请求只会直连，不读 Windows 系统代理——你这台机器直连 taostats.io 会超时，查询就静默退回本地索引，页面看到「0 次请求」便认定是没配 key（/api/overview 里 taostats_configured 明明是 true）。

0.8.16 起：出站会自动跟随 Windows 系统代理（Clash / v2rayN 等写在系统设置里的那种），一条路不通会自动换另一条（并打印 [taostats] 出站请求走 …），同时把「连不上」和「没有 key」分成两种提示。升级后仍失败，打开 「更新日志 → 环境自检」 看 「出站网络（taostats.io）」 这一项：

  • pass 当前走系统代理（http://127.0.0.1:7890）可达 → 网络正常；
  • warn 当前路径不通，但直连可用 → 代理软件刚掉过一次线，已自动切换；
  • fail 所有出站路径都不通 → 代理软件没开 / 系统代理没勾上，或被公司网络拦了。把代理软件打开再点一次自检。

想强制指定出站路径，可以设环境变量 WALLET_LINK_HTTP_PROXY：填 127.0.0.1:7890 用它，填 none 强制直连。

Q：Taostats 报 401 / 401 Unauthorized？ key 没填、填错，或 key 已在 Taostats 后台被删/重置（0.6.4 起 key 已保存在本机，重启不再丢失）。到 https://taostats.io/zh/pro/api-keys 重新复制一次，粘贴保存即可。如果提示 key 已失效，在后台删掉重新生成。

Q：能不能在 Mac 或 Linux 上用？ 可以，但需要手动建环境：装 Python 3.10–3.13，执行 python -m venv .venv、.venv/bin/pip install -r requirements.txt、.venv/bin/python run.py，然后访问同一地址。一键脚本只适配 Windows。

Q：数据存在哪？要不要备份？ 全部在 data\wallet_link.db 一个文件里（SQLite）。备份就复制这个文件；换电脑就带着 data\ 文件夹。

Q：怎么彻底卸载？ 先双击 停止.cmd，删掉整个文件夹和桌面快捷方式即可。没有写注册表、没有后台服务、没有开机自启项。
